Method: dual-agent（A 設計審查 · B 檢測器與瀏覽器實測），兩者互相隔離。
範圍：`web/src/setup/SourceStep.tsx` 的 `Tmdb` 與 `SourceCutaway`、`source.tmdb.*` 的兩份文案，

## Design specificity

**之間**：外框（泊位板、5:7 剖面 / 工作面、`.label` 依語言分岔、纜繩留下 `https://image.tmdb.org/t/p/`
這個實測值）是為這個產品寫的；閘門本身「小標題 + 徽章 + 導言 + 說明框 + 輸入框 + 主要按鈕 + 結果列」
是任何 SaaS onboarding 的「貼上你的 API key」面板。身份由 token 與周圍承載，不由這一塊承載。

**機械檢測器：0 findings**（`SourceStep.tsx`、`CompleteStep.tsx`、`SetupPage.tsx`，exit 0；改完之後又跑過一次）。

## 這一輪修掉的

- **P1 必填的那顆按鈕比可跳過的那顆安靜**（回歸）。改動一度把主要按鈕在欄位空白時停用，
  停用態是 `deck` 底，亮色主題實測對填色只有 1.03:1，讀起來是空框——正是票 11 抓到的
  「按不動的控制項讀起來像壞掉」在同一個檔案裡復發，而且中槍的是全精靈唯一的硬閘門。
  改成**按鈕永遠按得下去**，說不行的是欄位自己：`Field` 現成的 `error` prop（`role="alert"` +
  `aria-describedby`，實測 `aria-invalid=true`），不送出請求。新增 `source.tmdb.blank`。
- **P1 精靈唯一一次把人送去第三方網站，畫面上卻一個連結都沒有**（實測整頁 `a` 元素為 0）。
  網址原本只塞在 `CopyLine` 裡——那個元件的語彙是「可複製的指令」。改成連結與可複製網址**並存**：
  NAS 使用者的瀏覽器多半不在那台機器上，只給連結等於沒給。新增 `source.tmdb.open`。
- **P1 閘門的結果對輔助技術是靜音的**：隔壁索引站的 `<ol>` 有 `aria-live="polite"`，TMDB 這一條沒有。
  PRODUCT.md 的無障礙段落逐字要求「非同步結果要能被輔助技術讀到」，那是驗收條件。已補上
  `aria-live` 與 `aria-busy`。
- **P2 拿不到 key 的人是死路**：閘門區塊內補一句「現在就去申請也沒關係——進度已經存下來了，
  回來時還在這一步」（zh-Hant + en），不再只靠頁尾 12px 的泛用句子。
- **手機上閘門的主要動作不固定在拇指位置**：全精靈唯一沒有包 `STICKY_ACTION` 的主要按鈕，
  而它掛在一張約 2400px 長頁面的最底部。已補上（390px 實測無橫向捲動）。
- **失敗時可複製的「下一步」不可執行**：`fix` 說「確認這台機器連得到 api.themoviedb.org」，
  給的卻是設定頁網址。補一條真的跑得動的探測（image 裡沒有 curl，所以走 python，
  與 README 疑難排解同一個形狀）。

## 閘門本身的實跑（`--scenario bundled`，精靈推到第 6 步）

- 空欄按下「測試 TMDB」→ `aria-invalid=true`、`aria-describedby` 指到可讀的錯誤、**不送請求**。
- 泊位板停在 `BTH 3`（`aria-current="step"`），`BTH 4` 是「未指派」；`POST /api/setup/complete` 回 422
  `finish step 6 first: TMDB needs a credential that passes its test`。
- 貼上 32 hex 的 key 測過之後才跳到第 8 步，`complete` 回 200。
- 頁首在索引站結案之後確實印「泊位 BTH 3 · 第 6 步，共 8 步」。

## 沒有在這一輪修、已記進票的 `## Comments`

- **通過必填閘門之後泊位板 BTH 3 那一格不動**（詳情列只吃 Prowlarr 的探測結果）。信號色**會**變
  ——`sourceSignal` 要兩條纜繩都結案才轉 `secured`——但「哪一格現在缺什麼」沒有三重編碼。
  屬於泊位板的形狀問題，不是這張票的範圍。
- **A 說「第 6 步永遠不會被顯示」，實測是錯的**：索引站結案之後頁首確實印
  「泊位 BTH 3 · 第 6 步，共 8 步」（實測字串）。真正成立的是另一半——索引站還沒結案時停在第 5 步，
  而閘門已經畫在同一頁的下半截。
- **憑證是明文欄位**：repo 有 `PasswordField`，但同一畫面上索引站的 API key 也是明文 `Field`。
  只改一半會比現在更不一致；要改就三處一起改，另開票。
- 兩個 `h3` 都叫 TMDB（剖面抬頭 + 區塊標題）、頁面標題階層 `h3` 早於 `h2`、`break-all` 仍在 12 處
  ——都是 M0 帶過來的，與這張票無關。
- `complete.failed` 的文案在缺憑證時會錯怪後端。實際走不到（`current_step` 到不了 8），
  但值得在 M2 收設定頁時一起處理。

## 挑釁的問題（留給後續里程碑）

1. TMDB 既然是全新安裝與可用的 Berth 之間唯一的關卡，它為什麼是第 5–6 步的下半截，而不是自己一步、
   甚至排在可以跳過的索引站之前？
2. `api.themoviedb.org` 被擋住的使用者現在完全走不完精靈。「沒有 TMDB 就沒有 Berth」是想要的產品嗎？
3. 後端已經在認憑證的形狀（v3 32 hex / v4 JWT），要不要在打網路之前就擋掉明顯不是這兩種的輸入？
