# Shape：設定頁的 Jellyfin 連線摘要、介面登入、拿掉補舊集勾選（M4 票 78）

模式 **Operate**；全在既有的「泊位調度板」世界裡（DESIGN.md），不新增元件種類，只重組既有的。

## 1. Jellyfin 設定頁的「連線」

- **誰、何時**：精靈跑完之後的 admin，多半是 Jellyfin 搬了位址、或連不上時進來。要的是「現在接的是哪一台、還好嗎、能改什麼」。
- **形狀**：一張摘要（`panel` / `well` 底的 `<dl>`），四列：來源（套件內／既有）、位址（`value` 字）、版本（測試讀到的 `detail`，沒測到是「—」）、連線（信號 chip，與測試那一條同一套 `STATE_LABEL` / `SIGNAL_FILL`）。下面一句說為什麼換不了：擁有者是這台 Jellyfin 上的帳號，換一台等於換掉所有人的登入。
- **紅燈**：照舊說補法（`Fix`，套件內是 compose、既有是那一台）與「重新測試」；不另寫一套。
- **既有**：摘要底下一顆「改位址」，打開精靈的 `ExistingForm`（Jellyfin 只有位址一格——API key 是 Berth 自己向 Jellyfin 換來的，換 key 在下面「管理員登入」那一區）。存下照舊重測、另一台照舊被擋（`other_server`）。取消回到那顆鍵。
- **套件內**：沒有表單、沒有「改位址」——位址是 compose 固定的。
- **不做**：二選一卡片、`locked` 那句、段首的開發者說明。qBittorrent／Prowlarr 的連線區不動（二選一保留），但共用的 lede 拿掉「與精靈那一頁是同一塊」那半句。

## 2. qBittorrent／Prowlarr 設定頁的「介面登入」

- 慣例取一般 app 的「變更密碼」表單（GitHub／Jellyfin 自己的使用者設定）：先說現況，再三格，按一顆鍵。
- 段首一行「目前的帳號：X」（沒設過是「還沒設過」）；欄位：帳號（預填目前的帳號，改得了）、新密碼、再輸入一次；主鍵「儲存」，底下一行「改了之後舊的那一組就不能再用。」
- 拿掉「沿用 Jellyfin 帳密」與精靈的 lede（臨時密碼那段）。驗證（長度、冒號、兩次一致）、送出後的結果與失敗說法照舊。
- 精靈的 `InterfaceLoginFields`（含沿用）不動；它取消勾選時的三格抽成 `NewLoginFields`，設定頁只用這三格（密碼那一格叫「新密碼」），共用 `useInterfaceLogin` 的驗證（`reuse: false`、沒有 owner）。

## 3. 補舊集勾選

- `SeriesBinder`（Mikan 那一列）：勾選拿掉；「綁定之後會送出 N 集」換成一句說整季會一起補（媒體庫已有、已下載過的跳過，之後每天補一次漏掉的）；鍵是「綁定並送出」，不寫數字。非 Mikan 的照舊「綁定並送出 N 集」。
- `SubscribePanel`（Mikan 訂閱）：勾選拿掉，鍵是「訂閱並送出」（這一塊的動詞一直是訂閱）；說明句同上。
- `backfill` / `backfillOn` / `backfillOff` / `confirmBackfill*` / `subscribe.confirm*` 這幾個只為勾選存在的 key 刪掉。

## 狀態

連線：測試中、等待（啟動中倒數）、紅（補法）、綠；既有表單：測不過（標在位址欄）、另一台（拒絕）。登入：未設過、送出中、成功、被拒（原文）、請求沒走完。窄版 390：摘要的 `<dl>` 疊成一欄。
