# Shape：精靈與設定頁的錯誤分層（M4 票 21，2026-09-30）

使用者在 shape 回答了三題（都照建議）：

1. **通過的檢查也有「技術細節」**：行首只剩人話與關鍵值（路徑、分類名），端點、`dev=`、`inode=`、HTTP 狀態收進
   每一列都有的「技術細節」。GitHub Actions 每個 step 都能展開 log 的做法。
2. **失敗那一格的順序：人話 → 補法 → 技術細節**。Windows / macOS 錯誤對話框的「詳細資訊」、Home Assistant config
   flow（錯誤代碼由前端翻成人話、掛在欄位上）：先讀得懂，查證才展開。
3. **qBittorrent 連錯的預警是欄位下一行的中性提示**，不擋按鈕；被封之後才紅，說等多久或重啟。

## 形狀

- **一行人話**：由後端的封閉代碼（`StepFailure`）加少量參數（路徑、版本、媒體庫名）在前端選 i18n 文案；
  掛在造成它的那一條檢查或欄位上。後端字串不當標題。
- **補法**：照代碼與來源（套件內 / 既有）挑，指令只給適用的那一種。
- **技術細節**：原生 `<details>`，預設收起，`summary` 是 `.label`「技術細節」；內容是 `.value text-xs wrap-anywhere`
  的機器字串（端點、實測值、原文）。沒有內容就不畫。**一個元件**（`TechnicalDetails`），精靈、設定頁、健康頁共用。
- 未知例外是一個通用代碼（`unexpected`），人話說「沒預料到的錯誤」，原文照樣在技術細節裡。

## 不做

- 不把健康頁與精靈以外的頁面（Job、RSS、審核）一起改：它們的原文是另一種東西（入庫的原因），不在這張票。
- 不為了錯誤另開 dialog 或 toast（The Failure Expands In Place Rule 不變）。
