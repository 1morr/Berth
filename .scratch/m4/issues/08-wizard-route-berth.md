# 08 — 媒體庫路徑泊位：手動檢查、逐條收合、未確認的加路徑不放行

**Status:** ready-for-agent

**Blocked by:** 06（同一個精靈，前置段改完再動泊位）

**讀:** plan §9.3 第 3（既有 Jellyfin 的「加入 Berth 路徑」）、5 步、§9.5〈檢查與訊息〉；brief §19 2026-09-26「精靈與探索的試跑回饋」那一列；開工先 `/impeccable shape` 這一格

## 為什麼（2026-09-26 使用者試跑與 `berth-lab` 實測）

- **一進這一格就自動跑**（plan §9.3 第 5 步「走到這一格就自動跑」）。它不只是檢查：會建 qBittorrent 分類、在
  媒體庫目錄寫探測檔與硬鏈接測試檔——有副作用的動作要由人按。
- **五條纜繩 × 每條 Route 全部攤開**，四條 Route 就是二十列，「前往下一個泊位」被擠出畫面要往下捲。
- **既有 Jellyfin 的「加入 Berth 路徑」按了之後還要「確認加入」**，沒按確認也能直接「前往下一個泊位」，
  到這一格才發現那個媒體庫沒有 Berth 路徑。
- **slug 帶空格**：媒體庫叫「TV Shows」時 qBittorrent 分類是 `berth-tv shows`、下載路徑 `/complete/tv shows`
  （`berth/services/jellyfin.py:733` `library_slug` 只換掉路徑不收的字元）。

## 做什麼

1. 進這一格不自動跑；一顆「建立並檢查」（第一次）/「重新檢查」按鈕，按下之前說出會做哪些事（建分類、寫測試檔）。
2. 每條 Route 收成一列：名稱、寫入目標、「5 / 5 通過」；有一條失敗就自動展開那一條，全過預設收起。
   設定頁的 Route 列表用同一個元件。
3. 第 3 步「加入 Berth 路徑」的確認沒完成時，「前往下一個泊位」擋下並說出還差哪一步（或把確認併進同一個動作，shape 時定）。
4. `library_slug`：空白換成 `-`（中日文照留）。已經存在的 Route 與分類不改名（改分類路徑會搬走 torrent，brief §20.2），只影響新建的。
