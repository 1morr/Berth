# 頁 3 既有 Jellyfin：新建一個媒體庫、類型對得上的預設勾（M4 票 64 的 shape）

**Status:** confirmed（2026-10-14，使用者三題都照建議）

審計 E1（缺某類型的媒體庫時頁 3 多一列，勾了才建）、C2（類型對得上的預設勾）、P2-15（中文名與撞名）。
慣例來源：Seerr 的媒體庫選擇是「列出伺服器上的、逐個勾」；新建那一列對齊 Berth 自己套件內清單的
「類型＋名稱＋資料夾」三格（票 06f），不另立一套。

## 任務

既有 Jellyfin 只有劇集媒體庫、使用者想下載電影：原本卡片叫人先去 Jellyfin 建，離開 Berth 一趟。
這一頁的人已經是那台 Jellyfin 的管理員，在 Berth 裡勾一下就該建得出來——但那個媒體庫伺服器上所有人都看得到，
所以勾了才建。

## 拍板（使用者）

1. **勾選表最後一張卡片，預設不勾。** 勾了才展開：類型（電影 / 劇集，預設那台還沒有的那一種；兩種都有時電影）、
   名稱（照類型、照介面語言預填「電影」/「Movies」，可改）、資料夾（`<library root>/<slug>`，跟著名稱算、只顯示不能改）。
   卡片裡一句：這個媒體庫建在你的 Jellyfin 上，伺服器上所有使用者都看得到；之後改名或刪除在 Jellyfin 做。
   寫入目標固定是那個資料夾，不另外選。
2. **撞名就地擋下說原因，主鈕停用。** 名稱與那台已有的媒體庫同名（不分大小寫）：「已經有「X」了，在上面勾它就好」；
   資料夾已經是別的媒體庫的路徑、或是別的勾選中媒體庫要加的 Berth 路徑：「「X」已經在用 <路徑>」；名稱空白：要填名稱。
   建成之後那一列收回成未勾、名稱回到預填，新的媒體庫出現在上面的清單裡、已經有 Route。
3. **類型對得上的既有媒體庫預設勾**（電影、劇集；其他類型照舊不能勾），寫入目標照舊預設新的 Berth 路徑。
   預設勾的規則由後端給（`LibraryChoice.preselected`），整合測試守。

## 行為

- 「建立並檢查」的順序：先建勾了的新媒體庫 → 再替勾選的媒體庫加 Berth 路徑 → 建 Route。一段紅就停（現行規則）。
  新建那一段紅了，Jellyfin 的「建立媒體庫」那一條纜繩就地說原文（套件內同一條 `StepLine`）。
- 「按下之後會」清單多一行：在你的 Jellyfin 新建媒體庫「X」（<路徑>）。剖面的「這一輪會新建」照樣列它與寫入目標。
- 建媒體庫與套件內同一條路徑：同名的不重複建（重按、或建成之後 Route 檢查紅了再按，都不會長出「電影2」）。
- 那台一個媒體庫都沒有時：原本的「Berth 不替既有伺服器建媒體庫」改成「這台還沒有媒體庫，可以在下面新建一個」，
  新建那一列照樣在。
- 窄版：卡片內三格直排；類型是兩顆 radio，不用下拉。

## 不動

- 套件內那一側。
- 既有媒體庫的寫入目標選法、佔用規則、加路徑失敗的說法。
- 新建的媒體庫之後在 Berth 裡不能改名、不能刪（與套件內建的一樣，去 Jellyfin）。
- 一次只新建一個（一列）；要第二個，建完再勾一次。
