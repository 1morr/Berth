# 重裝之後在畫面上把帳本找回來（M4 票 60 的 shape）

**Status:** confirmed（2026-10-08，使用者不在場，照審計 E6 的拍板與既有文件自己決定；理由寫在每一條）

慣例來源：Sonarr / Radarr 的 Root Folder「Unmapped Folders」→ Library Import：磁碟上有、資料庫沒有的東西，
在根目錄那一頁列一個數字與一顆「匯入」，不在每一部作品上各問一次。Berth 這一顆就是 `rebuild-ledger`
（只加不刪、冪等），所以不必逐檔選，一顆做完。

## 任務

重裝或 DB 遺失之後，媒體庫的檔案都在、帳本是空的。使用者在作品頁看到「還沒有任何檔案入庫」會重複下載。
要讓他在三個會經過的地方知道「紀錄沒了、檔案還在」，而且只有一個地方真的按。

## 拍板

1. **偵測**：每一條 Route 的寫入目標底下、帳本上沒有的檔案。已經被重建或認領**判過**的不算——還開著而且寫了
   沒配上理由的 `unmanaged_library_file`，以及被忽略的那幾件。理由：重建之後配不上的檔案仍然不在帳本上，
   照字面算的話這顆按鈕永遠不會消失；對帳在 04:00 開的那幾件沒有理由，代表還沒有人試過重建，仍然算。
2. **按鈕在兩處、同一個元件**（`LedgerGapNotice`）：
   - **待處理頁最上面**（對帳那一行之上）：配不上的會變成這一頁的「非受管檔案」，結果就在同一頁往下看得到。
   - **精靈完成頁**（右欄 Route 卡片之後、各服務介面之前），只有偵測到時才畫。重跑精靈的人正是在這一刻；
     完成頁原本寫「跳過：沒有」，什麼都沒提。頁 5 已經驗過 TMDB，重建用得到。
   一句話說數字與為什麼（「多半是重裝過 Berth 或資料庫遺失：檔案還在，紀錄沒了」），一顆「從媒體庫重建帳本」，
   底下一行說後果（只加不刪、可以重按；配不上的不猜，變成非受管檔案）。按完就地換成結果：找回幾個、幾個變成
   非受管檔案；有 Route 或 complete 讀不到時另說一句並把原文收進「技術細節」。結果留著直到離開頁面，
   提示本身在重新偵測到 0 時消失。
3. **作品頁「檔案與版本」**：帳本空、但 Jellyfin 有這部（觀看區有回）時，不說「還沒有任何檔案入庫」，改說
   「Jellyfin 有這部，Berth 的紀錄裡沒有」加兩種可能（不是經 Berth 入庫的，或重裝、DB 遺失；不推測是哪一種——
   Berth 之前就在 Jellyfin 的作品也長這樣）；管理員多一個連到待處理的連結，一般使用者說請管理員重建。
   不在作品頁放按鈕：重建是整個媒體庫的事，在一部作品上按會讓人以為只動這一部。
4. **無主 torrent**：按鈕不改名，那一列多一行說明：選它是哪一部之後，Berth 建一筆下載接手這個 torrent，接下來
   照常規劃、入庫；重裝過的話先重建帳本，已經在媒體庫的檔案才會接回帳本上那一列（`importer._ledger_rows` 以目標
   路徑沿用），不另鏈一份。按鈕名留著是因為 `IssueAction` 的文案全站一致、改名要動 e2e，說明才是缺的。
5. **精靈完成後打開 `/setup`**：導向 Jellyfin 設定頁時帶一個參數，那一頁的 lede 之前多一行「精靈已經完成，之後的
   修改在這裡」。不另做 toast（The Failure Expands In Place Rule 的同一個理由：不浮在別處）。

## 不做

- 不在頁首導覽加徽章：提示不是一件 Issue，混進「N 件」會讓數字說謊。
- 不自動重建：寫 DB 的事要人按（brief §14，這一顆可逆但仍是寫入）。
- 不為偵測另開背景迴圈：打開待處理與完成頁時現算（走一次 Route 目錄，與對帳同一個走法）。
