# Shape：搜尋結果每一筆說得出歸到哪一類，用篩選按鈕看（M4 票 83）

2026-10-10 使用者確認：依類別分組、只標不是「符合」的列、自己打關鍵字不分類、上限符合 100 其他每類 50，其餘照稿。

## 工作與使用者

Media 詳情頁的搜尋區塊（Operate）。按下搜尋之後要挑一筆送單的人——通常是 admin，也可能是一般使用者。
現在畫面只說「100 筆名字對不上（已略過）」，那 100 筆根本沒送到前端；「收起來」的只能整批展開，每一筆沒說為什麼。
使用者沒辦法判斷 Berth 是不是判斷錯了（PRODUCT 原則 3、4：寧可停下來問；說得出原因）。

## 照誰的慣例

**Sonarr v4 互動搜尋**（`ReleaseController` 把每一個 decision 都回傳，`InteractiveSearchRow` 被拒的那一列一個紅色圖示，
popover 逐條列理由；篩選有 indexer）。Berth 跟它不同的兩處：

- **預設只開「符合」**（票面拍板）：Sonarr 預設「全部」，但 The Pirate Bay 對查不到的字會回熱門清單，全開等於回到票 08 之前。
- **一筆一類、一句話**，不是一串拒絕理由：Berth 的判斷是排了先後的粗篩，第一條命中的就是那一筆的歸類。

## 六類

2026-10-10 使用者追加：原稿的 `episode`（類型不符）與 `namesake_episode`（同名作品的集號）合成 `not_movie`——兩者說的是
同一件事（搜電影卻讀得出集數記號），只是證據不同；那一句話照樣帶出觸發的那段字。七類變六類。

**判定順序**（實作時改，見票的 Comments）：名字對不上 → 成人分類 → 不是電影 → 年份不符 → 只對上部分名字 → 符合。
證據硬的先、最軟的「只對上部分名字」最後：原稿把它排在集號之前，`Tsuki to Laika to Nosferatu - 05` 的片名也包住《Nosferatu》，
會先被它收走。按鈕與分組的順序照下表。

| 鍵 | 中 / 英 | 判準 | 那一句話（證據來自發佈名） |
| --- | --- | --- | --- |
| `fits` | 符合 / Matches | 其餘都沒命中 | — |
| `year` | 年份不符 / Wrong year | `misfit` 的年份那一條 | 發佈名寫 1990 年，這部作品是 1968 年。（劇集：不在這部作品的播出期間。） |
| `not_movie` | 不是電影 / Not a movie | 電影搜尋讀得出季集記號 `S04E02`、`Season 2`、`第2季`、`第05話`，或字幕組集號 `- 05`、`[01-12]`、`【12 END】` | 發佈名有集數記號「- 05」，這部是電影；多半是劇集，或同名的動畫。 |
| `adult` | 成人分類 / Adult | 分類碼 6000–6999 | 索引站把它分在成人類（6040）。 |
| `partial_title` | 只對上部分名字 / Partial title | 見下 | 發佈名的片名是「Law and Order SVU」，比這部作品的名字多一段：可能是衍生作品，也可能只是多寫了副標。 |
| `unrelated` | 名字對不上 / Other titles | `mentions` 為假 | 發佈名裡沒有這部作品的任何一個名字。 |

**「只對上部分名字」照 Sonarr**：取發佈名**第一個記號之前**那一段當片名（記號＝季集記號、字幕組集號、年份；片名自己帶的年份
不算），以 `/`、`|`、括號與文字系統（CJK／非 CJK；`_` 是 scene 的空白，不算分隔）切成一個一個名字；正規化後**有一個等於**這部作品的某個名字 → 不算；
沒有相等、但有一個**包住**某個名字 → 只對上部分名字。讀不出記號、或片名那一段沒有這部作品的名字 → 不判（算符合）。
所以 `Law.and.Order.SVU.S28E01` 是部分、`Law.and.Order.S24E01` 是符合、`Nosferatu - Eine Symphonie des Grauens (1922)`
（原文片名）是符合、`[ANi] SPY×FAMILY 間諜家家酒 - 05` 是符合（兩個名字各自比）、`Blade Runner 2049 2017` 不判。

**自己打關鍵字（票 08）**：一律 `unjudged`，不分類、沒有篩選按鈕、列上不標——Berth 沒有資格判斷那串字（打字多半就是因為
TMDB 的名字搜不到，分類的話幾乎每一筆都會是「名字對不上」）。沒有快照時同樣是 `unjudged`。

## API（`GET /search`，破壞性：SPA 是唯一的消費者）

- 每一列多 `verdict`（上表的鍵或 `unjudged`）與 `evidence`（觸發的那一段字：`1990`、`S04E02`、`- 05`、`Law and Order SVU`、`6040`；
  名字對不上與符合是空字串）。句子由前端拼（i18n），證據不翻。
- `rows` 是**各類各自逐站輪流取**之後合在一起：「符合」100 筆，其餘每類 50 筆（六類全滿最多 350 列，約 220 KB；解析每筆
  14 ms，最壞比現在的 200 列多兩秒）。
- `counts`：`{verdict, indexer, total}` 每一組一筆（總數，不是送出的數）——按鈕上的數字在「只看某個站」時跟著變。
- 拿掉 `discarded`、`set_aside`、`set_aside_total`；`total` 拿掉（＝`counts` 裡 `fits` 或 `unjudged` 的加總）。
- 筆數照樣加得起來：`returned = merged + Σ counts.total`。

## 畫面

- **筆數那一行**縮成「索引站回了 389 筆，其中 N 筆是重複的、已合併」——各類的數字搬到按鈕上。
- **一排篩選按鈕**（`FILTER` / `FILTER_ACTIVE`，`aria-pressed`，可多選），在結果表正上方：`符合 19 · 年份不符 250 · 不是電影 20 ·
  成人分類 19 · 只對上部分名字 0 · 名字對不上 100`。是 0 的不畫（「符合」例外，永遠在第一格）。
  按鈕列以 `role="group"` 加 `sr-only` 名稱。**做成可重用的元件**（`components/ToggleChips`，使用者 2026-10-10 追加）：
  票 84 的名字與季的選擇用同一種可點的 chip。
- **站別**：按鈕列尾端一個 `select`「所有站 / The Pirate Bay / Mikan …」（選項來自 `counts`），選了之後按鈕的數字與表格都只算那一站。
- **表格**：照現在的 `SearchResults`。開了好幾類時**依按鈕順序分組**（符合永遠在最上面），組內照排序鍵——不然熱門清單的
  五千個做種會壓在真正的結果上面。不是「符合」的列，發佈名下方一個中性小色塊（類別）＋一句理由（`ink-dim`）；「符合」的列不標
  （The Usual Stays Unpainted Rule）。照樣送得了單。
- **上限的說法**：某一類總數大於送來的筆數時，那一組末尾一行「這一類共 1070 筆，只列做種多的前 50 筆（每站輪流取）。」
- **空狀態**：每一顆都關掉 →「沒有選任何一類。」；開著的那幾類在這一站沒有東西 →「這一站沒有這幾類的結果。」；
  「符合」是 0 而其他類有東西 → 現在的 `onlyAside` 那一句改成指向按鈕：「沒有符合的結果；其他幾類有 N 筆，按上面的按鈕看。」
- 「收起來」的 `<details>` 展開區**刪掉**。
- 窄版（390）：按鈕 `flex-wrap`，站別 `select` 自己一列滿寬；列上的類別色塊與理由在發佈名下、送單鍵之上。
- `aria-live`：搜尋結束仍念「符合 N 筆」；切換按鈕不念（按鈕自己的 `aria-pressed` 已經說了）。

## 不做

- 解析度、字幕語言、來源這類篩選。
- 每一筆列多條理由（Sonarr 的 popover 清單）：一筆一類。
- 記住上次開了哪幾類：每次搜尋回到只開「符合」。
- 年份那一句說出劇集的播出期間是哪幾年（前端沒有最後一季的年份；說「不在播出期間」）。

## 已知的代價

- 「只對上部分名字」只在讀得出記號時判：`Law and Order SVU 1080p`（沒有季集、沒有年份）仍然算符合。
- 片名帶國別的 scene 寫法（`The.Office.US.S01E01`）是「只對上部分名字」：Sonarr 的 TVDB 片名是 `The Office (US)`，TMDB 沒有國別尾巴。
  拿掉國別的話 `Law.and.Order.UK`（衍生劇）就會算符合，兩者只看發佈名分不開。
- 「只看某個站」時標頭「結果表 N 筆」與 `aria-live` 仍說全部站的「符合」：按鈕與表格跟著站別變，標頭說的是這一次搜尋。
- 「名字對不上」只送 50 筆：The Pirate Bay 的熱門清單常常一百筆，看得到的是做種前 50 筆。
