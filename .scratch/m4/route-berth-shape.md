# 頁 3「媒體庫與路徑」：按鈕觸發、逐條收合（M4 票 08 的 shape）

**Status:** confirmed（2026-09-29，使用者兩題都照建議）

慣例來源：Seerr / Sonarr 加根目錄與下載器都是「填好 → 按 Test / Save」，不在進頁時動手；GitHub Actions 的
job 列表全綠收起、失敗的那一個展開（本 repo 的健康頁與 Route 設定頁已經是這個形狀）。

## 任務與第一個價值

走到這一頁的人剛接好 Jellyfin 與 qBittorrent，要回答「Berth 下載的東西會不會真的出現在 Jellyfin 裡」。
這一頁會動手（建媒體庫、在 Jellyfin 加路徑、建 qBittorrent 分類、寫探測檔與硬鏈接測試檔），所以**進頁不動手**，
一顆鈕、按之前說出會做哪幾件事，按完每條 Route 一列、壞的那條自己打開並說出怎麼改掛載。

## 拍板（使用者）

1. **套件內併成一個畫面一顆鈕**：媒體庫清單在上、Route 列在下；「建立並檢查」依序存清單 → 建還沒建的媒體庫
   → 建 Route 與分類 → 五條檢查。拿掉「開始靠泊」「前往 Route 與檢查」「媒體庫清單」三顆鈕與兩個畫面的切換。
   清單全部建好時收成一列（`<details>`，「媒體庫清單 · 3 個已建立」），要加一個再展開。
2. **既有 Jellyfin 的 Berth 路徑併進同一顆鈕**：還沒有 Berth 路徑的媒體庫，寫入目標多一個選項
   「（新）<path> — 按下建立並檢查時加到 Jellyfin」；按下時先加路徑再建 Route。沒有「確認加入」、沒有半途狀態。
   按鈕上面的清單就是確認：「在 Jellyfin 的 TV Shows 加入路徑 …（原本的路徑不動）」。

## 版面（工作面由上而下）

- h2、lede（套件內 / 既有各一句）、回頭看的說明。
- 套件內：版本太舊的警告；媒體庫清單（見上）；建媒體庫那一步失敗時那一條纜繩（原文與手動步驟）。
- 既有：勾媒體庫、選寫入目標（含上面那個「新」選項）；加路徑失敗時的原文與怎麼改掛載。
- **「按下之後會」清單**（這一輪真的會做的事，數字照目前的選擇算）→ 主鈕。主鈕：有新的可建是「建立並檢查」，
  否則「重新檢查 N 條 Route」；全綠又沒有新的時降成次要，主要動作是「前往下一個泊位」（每屏一顆 `assigned`）。
- Route 列：共用元件 `RouteRow`（健康頁、Route 設定頁同一個）：健康色塊、名稱、category、寫入目標、
  「5 / 5 通過」、展開 / 收起。失敗的那條預設展開，全過收起。展開是五條纜繩；精靈裡另有刪除。
- 剖面（左欄）只放纜繩列沒有的：兩個根目錄、這一輪要建的 Route（媒體庫 → 寫入目標），沒有就不畫那張表；
  拿掉「數量」那一列與七支端點的序列。

## 失敗時說出怎麼改掛載（既有服務）

第 2–5 條失敗而相關的服務是既有的：`download_path`（既有 qBittorrent）、`library_path`（既有 Jellyfin）各說
同一台主機、同一個父目錄掛在同一個容器路徑的條件；`probe_visible`（既有 Jellyfin）說它多半在另一台主機或掛在別的
容器路徑；`hardlink` 的 `EXDEV`（任一既有）說分開掛載（`/downloads`、`/tv`）要改成一條共同父目錄。
compose 片段照舊附上。健康頁與設定頁讀不到來源，這一句只在精靈（`RouteCheckList` 的 `existing`）。

## 狀態

- 進頁：只讀（`GET /setup/routes`、`GET /setup/jellyfin`），不送任何寫入。
- 按下：鈕變「建立並檢查中…」，泊位板那一格 `working`；建媒體庫那一段輪詢 Jellyfin 的步驟。
- 某一段失敗就停在那一段，後面的不送：清單被擋（列號）、建媒體庫失敗（纜繩）、加路徑失敗（原文）、建 Route 失敗。
- 四條 Route 全過：1280 × 720 與 390 × 844 不捲動看得到「前往下一個泊位」。
