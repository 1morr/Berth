# Shape：自己打關鍵字的搜尋分「對得上」與「對不上」（M4 票 83b）

2026-10-14 使用者選定三題：短字規則（CJK 不設下限、拉丁字短的要整詞）、鍵名 `typed_match` / `typed_miss` 並刪 `unjudged`、
文案「對得上／對不上」。推翻 `search-filter-shape.md`〈自己打關鍵字〉的「一律 `unjudged`」。

## 工作與使用者

作品頁搜尋區塊（Operate）。TMDB 的名字搜不到、自己在關鍵字欄打字的人。他要的是「含我打的那串字的發佈」，
不是 Berth 判斷「是不是這部作品」——那是票 08 不判的理由，仍然成立。這張只判斷**發佈名對不對得上他問的東西**，
讓 The Pirate Bay 的熱門清單（做種上千）不再壓在那幾筆真正的結果上面。

## 照誰的慣例

- **Prowlarr 手動搜尋頁**：打字搜、全部列出、只有站別與分類篩選，沒有相關性判斷——所以熱門清單在它那裡也是一樣淹掉結果。
  Berth 多做的一步是逐筆看發佈名含不含那串字，類似 Jackett 結果頁的「Filter」文字框，但預設就開著。
- **Sonarr v4 互動搜尋**（票 83 已查）：被拒的照樣列、可以送單；按鈕、分組、站別沿用票 83 的做法，不另起一套。

## 判準（後端，逐筆）

- **對得上**（`typed_match`）：發佈名含打的那串字，**或**含這部作品的任何一個名字。沒有快照時只看第一條。
- **對不上**（`typed_miss`）：兩條都沒有。
- **「含」怎麼比**（兩條共用同一個規則）：正規化（`normalize_title`）之後——
  - 那串字有 CJK：照包含比，不設長度下限（「無間道」三個字也算）。
  - 純拉丁字、正規化後不到 4 個字（`_MIN_CONTAINED`）：要**整詞**相等（打 `Up` 對得上 `Up.2009.1080p`，對不上 `Setup`）。
  - 其餘照包含比。
- 第二條在這條路上用上面的規則比作品的每個名字，**`mentions` 不動**：照作品名搜的六類與判定順序照舊。
  所以只寫簡體「无间道」的發佈在打「無間道」時也對得上（專案沒有繁簡轉換，不為這張引進）。
- 自己打關鍵字仍不判年份、類型、成人、部分名字。

## API（`GET /search`，破壞性：SPA 是唯一的消費者，CHANGELOG 寫明）

- `SearchVerdict` 多 `typed_match`、`typed_miss`，**刪 `unjudged`**：沒有快照時也照第一條判，而照作品名搜沒有快照時根本沒有查詢（`NO_QUERY`），它再也走不到。
- 「對得上」送 `RESULT_LIMIT` 筆、「對不上」送 `OTHERS_LIMIT` 筆，各自逐站輪流取；`counts` 形狀不變；`returned = merged + Σ counts.total`。
- `evidence` 兩類都是空字串：打的字不是發佈名裡的一段，前端用它自己送出的那串字。

## 畫面

- 沿用票 83 的 `ToggleChips`、分組、站別下拉，只是自己打字時按鈕只有兩顆：`對得上 N · 對不上 N`（Matches · No match）。
  「對得上」永遠在第一格（是 0 也畫），「對不上」是 0 不畫。預設只開「對得上」；每次搜尋回到預設。
- 「對得上」的列不標（The Usual Stays Unpainted Rule）。「對不上」的列：中性色塊「對不上」＋一句
  「發佈名裡沒有「無間道」，也沒有這部作品的名字。」／ “The release contains neither “無間道” nor any of this title’s names.”
  （實作時拿掉了「沒有快照時只說打的字」那個變體：前端分不出這一次有沒有快照，只差在句子後半多說了一件 Berth 沒查的事。）
- 「對得上」是 0、「對不上」有東西：「沒有對得上的結果；對不上的有 N 筆，按上面的按鈕看。」
- 標頭「結果表 N 筆」與 `aria-live` 說「對得上」的數（與照作品名搜時說「符合」同一件事）。
- 窄版、空狀態（沒選類、這一站沒有）、上限那一行、`aria-pressed` 全照票 83。

## 不做

- 偵測整站是熱門清單、把那一站藏掉。
- 繁簡轉換程式庫。
- 改排序的預設欄位。
- 標出「這一筆是靠作品名才對上的」：一筆一類，對上就是對上。

## 已知的代價

- 拉丁字短詞要整詞：發佈名把它跟別的字黏在一起寫時對不上（打 `Ted` 對不上 `TedLasso.S01E01`）——打四個字以上就照包含比。
- 打的字很泛（`1080p`）時熱門清單也會對得上：那是使用者問的東西。
- 作品名太短時第二條也會讓熱門清單對得上（code-review Spec 軸）：作品叫 `It`、`Up` 時，`It.Ends.With.Us` 有 `it` 這個詞；
  一兩個字的中文名、`titles` 裡各國的短別名同理。照稿：第二條與第一條同一個規則。
- 打好幾個詞時是整串比：打 `Infernal Affairs 1080p` 時 `Infernal.Affairs.2002.1080p` 不含這串字，只靠第二條（作品名）對得上；
  沒有快照時就歸對不上。
- 打的字正規化後什麼都不剩（純西里爾、希臘、泰文：`normalize_title` 只留拉丁英數與 CJK）時，第一條永遠不成立，
  多半每一筆都是對不上、預設什麼都不列——比 `unjudged` 全列還退步。少見，記著不修。
- 照作品名搜時 3 個字的中文名照舊不算（`mentions` 的下限沒動）：《無間道》照作品名搜，`無間道 III [国语中字]` 仍是「名字對不上」。另開票處理。
  票 83c 已處理：照作品名搜的中文名三個字起就比；兩個字的照舊不算（使用者 2026-10-19 選定）。
