# 套件內 qBittorrent / Prowlarr 的介面帳密（M4 票 07 的 shape）

**Status:** confirmed（2026-09-28，使用者兩題都照建議）

慣例來源：Umbrel、CasaOS 這類套件商店給每個 app 一組已知的登入；Prowlarr 自己的「需要驗證」對話框
與 Jellyfin 的啟動精靈建立登入時密碼打兩次；Sonarr / Jellyfin 的設定頁密碼欄留空代表不改。

## 任務

`docker compose up` 的人之後自己打開 qBittorrent WebUI 或 Prowlarr 時，要知道拿什麼登入。Berth 自己
不需要它（qBittorrent 靠免密白名單、Prowlarr 靠掛載讀到的 API key），所以文案要說清楚：這是**那個服務
自己的登入**，給你用的。

## 決定

- **兩格都必填**（使用者拍板）：qBittorrent 留空只剩容器 log 裡每次重啟都換的臨時密碼；Prowlarr 留空
  則第一次打開時它自己要人設，違反「一個介面完成所有事」。第一次必填；設過之後（回頭看、設定頁）
  密碼欄空著代表不改。
- **帳號預填擁有者名字，密碼自己打兩次**（使用者拍板）：擁有者的密碼不存下來（票 06），而設一組新登入
  就是建立——打錯了沒有人會告訴他（票 06「密碼打兩次只在建立時」）。兩格各自獨立，不回到「同一組」勾選框。
- **既有的那一台沒有這一格**：剖面照舊，不出現欄位（票 05：不寫既有服務的帳密）。後端收到既有服務的
  帳密回 422，一個字都不送。

## 泊位（精靈）

- 泊位 2（qBittorrent，套件內）：工作面在纜繩序列上方放「qBittorrent WebUI 登入」一組欄位（帳號、密碼、
  再一次密碼），跟著「套用」一起送；密碼那一條纜繩照舊在序列裡。剖面「WebUI 登入」一列：還沒設是
  「將設定 · 名字」/「尚未設定」，設過是名字。
- 泊位 4（索引站，套件內 Prowlarr）：同一組欄位放在勾選清單與「加入」鈕之間，跟著「加入」一起送。
  「之後再說」照舊可跳過整步（包含登入），完成頁說出跳過了什麼。
- 步驟導出：套件內那一台的登入那一條要有結論（`ok` 或「已經是這一組」）才算這一步做完。

## 設定頁

- 設定 → qBittorrent、設定 → 索引站：套件內時多一區「介面登入」，同一個欄位元件，自己的「更新登入」鈕；
  只寫登入，不連帶還原偏好或重驗站。帳號預填目前那一組，密碼兩格空白、必填（改登入就是設新密碼）。
- 既有時沒有這一區（位址與 Berth 連它用的帳密在「連線」區，那是另一回事）。

## 無障礙與文案

欄位與錯誤以 `aria-describedby` 關聯（沿用 `Field`），兩次密碼不同時就地說；說明句寫「Berth 自己用不到
這組，是給你打開 qBittorrent / Prowlarr 介面用的」。zh-Hant 與 en 並列。
