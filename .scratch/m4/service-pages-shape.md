# 服務頁：每個服務手動選擇（M4 票 15 的 onboard shape）

**Status:** confirmed（2026-09-29，使用者兩題都照建議）

慣例來源：Seerr 連 Jellyfin、加 Sonarr / Radarr，Sonarr / Radarr 加下載器，全都是「手動填 → Test → Save」，沒有
自動偵測（brief §20.14）。Seerr 的媒體伺服器也是精靈第一頁、之後不在精靈裡換。

## 任務與第一個價值

打開精靈的人要回答的第一件事是「這個服務是 Berth 帶來的那一台，還是我自己的」。以前 Berth 替他猜，猜錯就寫到他
的服務上（票 05）。現在由他說，Berth 說出每一種選擇的後果，選完當場測給他看。

## 頁面與順序

泊位板五格，沒有前置列：Jellyfin（BTH 1，擁有者）→ qBittorrent（BTH 2）→ 媒體庫與路徑（BTH 3）→ Prowlarr 與
索引站（BTH 4）→ TMDB（BTH 5）→ 完成。頁號就是步號（1–6）。

## 服務頁的共同形狀（頁 1、2、4）

```
[h2 這個服務是哪一台？]                                   剖面：將會做什麼
 ┌ 套件內 ───────────────┐ ┌ 既有 ────────────────────┐   套件內 · 連 http://qbittorrent:8080
 │ compose 帶來的那一台  │ │ 你自己已經在跑的那一台    │   既有   · 只用 Berth 自己的分類
 │ Berth 連 qbittorrent: │ │ 同一台主機、同一個父目錄  │
 │ 8080，代為設定        │ │ 掛在同一個容器路徑；從    │
 └───────────────────────┘ │ COMPOSE_PROFILES 拿掉     │
                           └───────────────────────────┘
 [測試那一條：信號 · 服務 · 位址 · 結果 / 倒數 / 補法 · 重新測試]
 [這一頁自己的事：擁有者表單 / 偏好與登入 / 索引站]
```

- **兩格是一組 radio**，窄版上下疊。**不預選**（使用者拍板：猜錯正是這張票要消滅的）。進頁與選擇之前不發任何探測。
- **點「套件內」就存下並測試**（唯讀，只連 compose 主機名，不寫任何東西）。**點「既有」只展開表單**：位址 + 那個服務
  要的憑證（Jellyfin 只要位址——管理員帳密在擁有者表單；qBittorrent WebUI 帳密；Prowlarr API key 或 Torznab），
  按「測試連線」才存下並測試。測不過也存，改一個欄位再按。
- **「既有」的說明**：Jellyfin、qBittorrent 說出同主機、同容器路徑的條件；三個都說出要從 `.env` 的
  `COMPOSE_PROFILES` 拿掉哪一個（`CopyLine` 給不含它的那一行），忘了拿掉也不致命。
- **測試那一條**沿用纜繩（`MooringLine` 的形狀）：
  - 套件內主機名解不到 → 紅：「把 `qbittorrent` 加回 `.env` 的 `COMPOSE_PROFILES` 再 `docker compose up -d`」，兩行可複製。
  - 套件內連不上 / 503 / 回的不像它 → 工作中，每 3 秒重測，倒數到 2 分鐘；逾時紅燈給「重新測試」。過了上限仍是
    協定不符 → 那個主機名上是別的東西。
  - 既有的當場給結論（連不上、帳密不對、被封 IP、缺 key 各自一句）。
  - 綠燈說版本（Jellyfin 另說它初始化過了沒、qBittorrent 版本、Prowlarr 站數）。
  - 「重新測試」只在紅燈那一條上（取代「重新偵測這個服務」）。
- 綠燈之後，這一頁自己的事出現在測試那一條下面。

## 回頭改選擇（使用者拍板）

- **Jellyfin 在擁有者成立之後鎖住**：兩格照畫、選中的那一格標著，另一格不可點，旁邊說「擁有者是這一台上的帳號，
  換一台 Jellyfin 等於換擁有者；精靈跑完之後在設定 → Jellyfin 換位址」。後端同一條：擁有者之後改 Jellyfin 的來源回 409。
  同一個來源換位址（設定頁的連線區）照舊可以。
- **qBittorrent / Prowlarr 隨時可改**：這一頁有結果時，點另一格先就地警告：「Berth 已經寫進原本那一台的
  偏好 / 登入 / 站留在那裡，不會撤回；這一頁要重做」。實作時的形狀（不是 `ConfirmAction`）：換成套件內是警告下一顆
  「改用套件內的那一台」與取消；換成既有是警告貼在展開的表單上方，**按「測試連線」就是確認**——既有本來就要填位址才能
  測，多一顆確認只是多按一下。改了之後那一頁的結果清掉；qBittorrent 改了，所有 Route 的檢查
  標成未檢查（分類建在舊的那一台上），媒體庫與路徑頁要重新檢查才走得過去。

## 表單跟著那一台的狀態走

- Jellyfin：測試綠燈時已經知道 `StartupWizardCompleted`。還沒初始化（選既有也一樣）→「建立 Jellyfin 管理員」（密碼兩次）；
  已經有管理員（套件內重裝保留 config 也一樣）→「用 Jellyfin 管理員登入」（一次）。
- qBittorrent / Prowlarr（套件內）：已經設過介面登入就不強迫再設——說出帳號、給「更換登入」。怎麼認得（實測，brief §20.14）：
  - qBittorrent：`app/preferences` 讀不到密碼（`web_ui_password` 只寫不讀），只有 `web_ui_username`；全新的那一台是預設的
    `admin`、密碼沒設（log 裡是臨時密碼）。**帳號不是 `admin` 就當成設過了**；還是 `admin` 的一律當沒設過（寧可多問一次）。
  - Prowlarr：`config/host` 的 `authenticationMethod` 全新是 `none`、帳號空白；設過是 `forms` / `basic` 加帳號。

## 沿用 Jellyfin 帳密（brief §16.3）

介面登入那一組上面一個勾選框「沿用 Jellyfin 帳密」，預設勾選：勾著時帳號就是擁有者（唯讀顯示）、密碼打一次；Berth 先向
Jellyfin 驗過再寫。驗不過就地說「這不是 <擁有者> 的 Jellyfin 密碼」，兩台都不寫。取消勾選回到票 07 的三格（密碼兩次）。
設定頁的「介面登入」一區同一個勾選。剖面「不存下 · 你的密碼」照舊成立：Berth 只記帳號與加鹽雜湊。

## 無障礙與文案

兩格是 `role="radiogroup"` 的真 radio（方向鍵可切換、焦點可見）；鎖住的那一格 `aria-disabled` 並以文字說明原因。測試那一條
是 `aria-live="polite"`。zh-Hant 與 en 並列。
