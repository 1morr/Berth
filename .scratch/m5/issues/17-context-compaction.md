# 17 — 上下文自動壓縮與 `/compact`

**Status:** ready-for-agent

**Blocked by:** 16

**讀:** plan §11.6〈上下文管理〉〈用量記錄〉〈provider〉（固定前段）；CONTEXT.md 的 Compaction；`docs/research/` 票 07 的 context window 與壓縮結論

## 為什麼

對話一長就會撞到模型的 context window，或是每一輪都重送一大堆舊的工具結果。使用者要的是 claw 那種自動管理：快滿時自己收、也可以打 `/compact`。做在 services、與 provider 無關，因為 OpenAI 相容的端點不一定有伺服器端的壓縮。

## 做什麼

1. **何時壓**：上一次呼叫回報的輸入 tokens 超過模型 context window 的一個比例（預設 70%，寫進 plan §11.6）。window 照票 07 的取法；不知道時用保守的預設。usage 沒回輸入 tokens 時用估算，並在票上寫怎麼估。
2. **怎麼壓**，兩段：
   - 先把較舊的工具結果換成一行「已收起」加 id（結果卡的資料仍在 Berth 的資料庫裡，畫面照舊畫得出來）。
   - 還不夠，才叫模型把較早的對話摘要成一則，保留之後還要用的 id（release、作品、Feed、Proposal）與使用者做過的決定；最近幾輪原樣保留。
3. **之後接得上**：壓縮之後，模型以 id 指到壓縮前搜出來的 release，照樣送得出去——票 12 的「這則對話搜出來的」判定讀的是 Berth 存的紀錄，不是模型的上下文。
4. **`/compact [要保留的重點]`**：手動觸發，重點文字併進摘要的指示。
5. **保險絲**：一輪最多壓一次；摘要那次呼叫失敗就照舊送（可能撞上限、把原因說出來），不重試成迴圈。
6. **記帳與畫面**：壓縮那次呼叫寫 `ai_calls`，出處是壓縮；畫面在壓縮處畫一條分隔線，說收起了什麼；對話全文仍存在 Berth、捲得回去。
7. 固定前段（system、工具定義、skill 索引）壓縮前後逐字相同，快取只失效在被換掉的那一段之後。
