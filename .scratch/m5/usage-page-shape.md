# 用量頁 shape（M5 票 13）

2026-10-24，`/impeccable shape`。使用者答了三題：放設定的新分頁「用量」；明細除了出處，還要依格式與模型、依人、依失敗類型；趨勢是每日一根直條加表格。

## 工作與讀者

- **誰**：管理員，偶爾打開（換了模型或第三方端點之後、月底看帳單之前）。不設預算（brief §6.10），這一頁只回答「用了多少、快取有沒有吃到、誰在用、被擋了幾次」。
- **模式**：Operate。掃一眼就讀得出數字，對得齊比好看重要。
- **成功**：一屏內看到期間的總量與命中率；看得出哪一天特別多；換模型後比得出兩個模型的命中率；知道有幾筆沒回報快取欄位，命中率的分母因此少了誰。

## 採用的慣例

**Anthropic Console 的 Usage 頁**：依日的堆疊直條、依 token 種類分段、可依模型分組、期間切換；**OpenAI 的 Usage 頁**也是依日直條加表格。照它們的「依日直條 + 依種類分段 + 可分組的表」，不做它們的金額（Berth 不設預算、不知道第三方的價格）。期間放在網址（`?days=30`），與 Grafana、Vercel 的時間範圍一樣重整與分享不丟。

## 結構（由上而下，`SettingsFrame` 單欄 `max-w-3xl`）

1. **分頁列**多一格「用量」，接在「AI」後面（同在泊位那五格之外）。路由 `/settings/usage`，API `GET /api/settings/ai/usage?days=7|30|90`，都在 `/settings` 前綴下，門禁擋 `user`。
2. **期間切換**：7 天 / 30 天 / 90 天，預設 30；與頁首導覽同一種方塊（`NAV_LINK` 的當前樣式），是連結不是按鈕。期間以容器時區的日期算，含今天（與週報同一個時區規則）。
3. **總量列**（`dl`，與泊位板一樣 `gap-px` 的格子，不上信號色）：呼叫數、輸入 tokens、輸出 tokens、快取命中率、沒成的次數。命中率格底下一行小字：「N 次沒回報快取，不算在內」（N = 0 時不出現）。分母是 0 時印「—」並說「這段期間沒有回報快取的呼叫」。
4. **依日直條**：每一天一根，含沒有呼叫的日子（空位，只剩基線）。高度是當天 tokens，分三段由下而上：**快取讀取**、**其他輸入**（全部輸入扣掉快取讀取；含快取寫入、沒快取到的、沒回報快取的）、**輸出**。直角（DESIGN.md 零圓角，壓過 dataviz 的 4px 圓頭），柱與柱 `gap-px`。圖例在圖上方一行三個小方塊加字。沒有浮動 tooltip（這套系統沒有 z 軸）：圖上方一行**讀數列**，平常說期間最後一天，滑過或聚焦一根就換成那一天（日期 · 三段的數 · 呼叫數 · 命中率）。~~每根是可聚焦的元素~~（實作時改：九十根各自可聚焦是九十個 Tab 停留點）圖本身 `aria-hidden`、不可聚焦，表格才是鍵盤與螢幕閱讀器的等價物；讀數那一行是一般文字。
5. **逐日表**：原生 `<details>` 預設收起（「逐日數字」），只列有呼叫的日子：日期、呼叫、輸入、輸出、快取寫入、快取讀取、命中率。
6. **依出處**、**依格式與模型**、**依人**、**沒成的**：四個 `SettingsSection`，各一張表。前三張欄位相同（呼叫、輸入、輸出、快取寫入、快取讀取、命中率）；格式與模型那張的一列是「模型 id」加一行 `.value text-xs` 的「格式 · 主機」（同模型不同端點分開列）；人那張的 `user_id` 是空的一列叫「沒有人（背景任務或已刪除的使用者）」。沒成的那張：失敗類型（`AiFailure` 的 i18n）、次數；全部成功時這一區只印一句「這段期間沒有失敗」。
7. 版本行（`BerthVersion`）照舊在最下面。

## 顏色

三段是同一個色相的三階中性（dataviz 的 ordinal ramp），不借信號色（The One Meaning Rule；用量不是狀態）。驗證器 `validate_palette.js --ordinal` 對 `well` 底實跑：

| 段 | 深色 | 亮色 |
| --- | --- | --- |
| 快取讀取 | `ink` | `ink` |
| 其他輸入 | `ink-dim` | `ink-dim` |
| 輸出 | `rule-strong`（4.51:1） | 新 token `--color-bar-faint` = `oklch(0.58 0.014 245)`（3.29:1；`rule` 只有 1.76:1，不過） |

新 token 只給圖用：`--color-bar-faint`，深色值等於 `rule-strong`。字一律 `ink` / `ink-dim`，不用段的顏色。

## 狀態與範圍

- **一筆都沒有（有史以來）**：整頁只剩一塊 `Notice`（中性）：還沒有任何 AI 呼叫；到「設定 → AI」填好端點與模型、按「測試」，之後側面板的對話也記在這裡；一顆連到 `/settings/ai` 的 Ghost 鍵。不畫空圖、不畫一排 0。
- **這段期間沒有、之前有**：總量列照畫（全是 0、命中率「—」），圖只剩基線，一句「這段期間沒有呼叫」加連到 90 天的連結（已經是 90 天就不給）。
- **範圍**：家用，一天 0–數百次；tokens 一天到百萬級。數字用 `Intl.NumberFormat` 依語言分位；~~總量列另給縮寫~~（實作時拿掉：九位數在五格裡放得下，縮寫在中文是「萬」，與表格的數對不上）。90 根在 390px 寬約 3px 一根，仍畫得出來；不換成週。
- **讀取中**：總量列與圖的位置是不動的 `deck` 色條，與真的一樣高。**讀不到**：`RequestFailed`。

## 窄版

- 總量列 `grid-cols-2`（2+2+1，最後一格橫跨），`sm` 以上一列五格。
- 表格窄版只留第一欄、呼叫、命中率；其餘收到第一欄底下的 `.value text-xs`，每一格自己說它是什麼（「輸入 12,345」），一份 DOM 兩種版面。實跑後改成**一組一行**：一行中點分隔在 390 寬一定斷行，斷開的那一行以中點開頭。

## 不做

金額與價格、預算與警示、依小時、匯出 CSV、逐筆呼叫清單（AI 活動頁是票 14 的事）、自訂日期範圍。

## 契約（給實作）

`GET /api/settings/ai/usage?days=30` 回：

- `has_any`：有史以來有沒有任何一列（分「第一次」與「這段期間沒有」）。
- `since`、`until`：期間的第一天與最後一天（容器時區的日期）。
- `totals`：一份 `UsageTally`。
- `days`：每一天一份（含沒呼叫的日子），`date` + `UsageTally`。
- `by_origin`、`by_model`（`format`、`host`、`model`）、`by_user`（`user_id`、`name`，可為 `null`）：各一串 `UsageTally` 加鍵。
- `failures`：`AiFailure` → 次數。

`UsageTally`：`calls`、`failed`、`input_tokens`、`output_tokens`、`cache_write_tokens`、`cache_read_tokens`（各自只加知道的，`NULL` 不當 0 也不讓整格變不知道）、`hit_rate`（`null` = 分母是 0）、`cache_unreported`（快取讀取是 `NULL` 的呼叫數）。命中率 = Σ 快取讀取 ÷ Σ 輸入，**只加輸入與快取讀取兩格都知道的呼叫**（plan §11.6〈用量記錄〉）。
