# Shape：媒體庫頁 `/library/:routeSlug` 與 Media 詳情的檔案、版本、各集狀態（票 13）

`/impeccable shape`，2026-09-15。視覺世界沿用 DESIGN.md「泊位調度板」，不新開世界。
Media 詳情頁的區塊序列沿用 `.scratch/m1/media-detail-shape.md` §3（本票填第 4 塊，並在第 2 塊加一欄）。

使用者拍板四件事：

1. **牆上放這條 Route 上有 Job 的全部作品**（含下載中、待審、失敗），不是只放帳本裡有檔案的——
   否則「有待審」「有 Unmatched」兩個篩選找不到從沒入庫過的作品。
2. **深連結的位址 = 選填的「Jellyfin 對外網址」＋自動推導**（Seerr 的 `externalHostname` 慣例）。
3. **各集入庫狀態五種**：已入庫 · 下載中 · 卡住 · 缺 · 未播出。
4. **卡片本體連 Berth 的 Media 詳情**，標識帶上另有一條「在 Jellyfin 開啟」；兩個連結並排，不巢狀。

## 1. 工作與讀者

- **模式：Operate。** `admin` 與 `user` 都進得來（瀏覽不是管理動作，brief §11）。
- **兩個時刻**：「我想看那部片」——認出作品、一鍵到 Jellyfin；以及「怎麼那部還沒好」——
  一眼看出哪一部需要人，點進詳情看是哪個檔案。brief §12：這一頁的價值在**狀態與修正**，不在播放。
- **從哪裡來**：頁首導覽多一項「媒體庫」；Media 詳情頁仍從探索牆與下載列表進來。

## 2. 成果與證據

- **主要任務**：在一條 Route 裡認出一部作品的入庫狀態，然後二選一——到 Jellyfin 播，或進詳情修。
- **只有 Berth 說得出來的真話**（Jellyfin 與 qBittorrent 各自都說不出來）：
  1. 這部作品在這條 Route 上**入庫了幾集、TMDB 上播了幾集**（`10 / 38 集`）。
  2. **Jellyfin 找到它了沒**——反查狀態（帳本的 `jellyfin_item_id` / `resolve_attempts` / `resolve_after`）。
  3. **哪一部需要你**：待審、Unmatched、送單或入庫失敗。
- **真實資料範圍**（票 12 的驗收那一套，現在還開著）：
  - The Bear（TV）S03 10 集入庫，TMDB 上三季 28 集已播；Frieren（Anime）S01 28 集 + Specials 11 集；
    Oppenheimer（Movies）1 個檔案。三部的 50 個檔案全部反查到。
  - 一條 Route 上從 0 部到幾百部；一部作品 1 到 1213 集（柯南）；一集 1 到數個版本。
  - Specials（S00）不進「N / M 集」的總數（票 04 的同一條），但各集狀態照樣列出。

## 3. 選定方向

- **視覺權威**：DESIGN.md。卡片沿用探索牆 `MediaTile` 的語彙（海報 + 標識帶、每格自己的 `border-2`、
  格線不靠 `gap-px`），網格斷點相同（2 / 3 / 4 / 6 欄）。
- **結構論點：同一座堆場的盤點表。** 探索牆是「港外的船」，媒體庫是「已經靠岸的貨」——
  同一種貨櫃，標識帶上多蓋了一行盤點數字與一條通往 Jellyfin 的纜繩。
- **頁面序列**：抬頭（`媒體庫`）→ Route 切換列 → 篩選列 → 卡片牆。
  - **Route 切換列**是一排連結方塊（與頁首導覽同一種外觀），每條 Route 自己一個網址，
    不是 tab 元件：`TV 2` · `Anime 1` · `Movies 1`。當前那一條重橫線 + `deck` 底 + `aria-current="page"`。
  - **篩選列**是第二排較小的連結方塊：`全部` · `待審 N` · `Unmatched N`，狀態在網址上
    （`?filter=review` / `?filter=unmatched`），重新整理與分享都留得住。
- **焦點時刻**：一整面牆裡**只有需要人的那幾格塗了漆**。常態（已入庫、部分）是中性色塊，
  例外才塗：下載中 `working`、待審 `assigned`、失敗 `blocked`。這一頁不做綠色勾勾牆。
- **實作後果**：卡片的狀態、計數、篩選旗標與 Jellyfin 連結狀態全部由後端算好
  （`GET /api/library/{slug}`），前端只照畫；唯一留在前端的是「瀏覽器現在的主機名」那一段推導（§7）。

## 4. 範圍與邊界

- **範圍**
  - `/library`（導向第一條啟用中的 Route）、`/library/:routeSlug`、頁首導覽項。
  - `GET /api/library`（Route 清單與各自的作品數、兩個篩選的數字）、`GET /api/library/{slug}`（卡片）。
  - Media 詳情：第 2 塊集表加「入庫」一欄、季列加 `已入庫 N / M`；第 4 塊「檔案與版本」
    （`GET /api/media/{id}` 多帶 `files` 與 `versions`，plan §6 的 media 列本來就寫著「檔案 + Unmatched + 版本」）。
  - `jellyfin_resolver` 反查時一併記下劇集的 **Series item id**（Episode 自己帶 `SeriesId`，
    2026-09-15 對 12.0.0 實測），卡片深連結到作品而不是某一集。
  - `JellyfinSettings` 多一個選填的**對外網址**，在服務設定頁改（只有 admin）。**build 定案：自己一個區塊**
    （服務卡片之後、qBittorrent 漂移之前），不塞進 Jellyfin 卡片——卡片是健康檢查的診斷區塊，健康頁
    也在用同一個元件，放進去會讓健康頁多一個它不該有的表單。
- **不做**：Issue 篩選（M2）、rematch / 指派 / 刪除（M2）、排序與搜尋、分頁、內嵌播放器（brief §12）、
  重抓海報、「全部在 Jellyfin 開啟」。
- **不碰**：探索頁、下載列表頁、Media 詳情的身分帶與搜尋區塊、設計 token。
- **反目標**
  - 不做 Jellyfin 式的整寬背景大圖與 hero；海報維持 2:3 一格塗裝。
  - 不讓整張卡片直接開 Jellyfin（使用者拍板）；不做連結裡面包連結。
  - 不做綠色勾勾牆：「已入庫」不塗 `secured`。
  - 不做 hover 才出現的資訊；不做骨架屏動畫。
  - 不把「還沒反查到」畫成一條點了會 404 的死連結（票面驗收）。

## 5. 狀態與範圍值

### 媒體庫頁

| 狀態 | 樣子 |
| --- | --- |
| 一條 Route 都沒有 | 一句說明 + `SetupHint`：admin 連到精靈泊位 4，`user` 看到「請管理員建一條 Route」 |
| 這條 Route 還沒有作品 | 「這條 Route 還沒有任何作品」+ 下一步：到探索頁找一部，搜 torrent 時「入庫到」選它 + 回探索頁連結 |
| 篩選後沒有 | 「沒有待審的作品」/「沒有 Unmatched 的作品」+ 回「全部」的連結 |
| 網址上的 slug 不存在 | 「沒有叫 `xxx` 的 Route」+ 連到第一條 |
| 停用的 Route | 仍列在切換列上，帶中性色塊「停用」；牆照樣畫得出來（已入庫的東西還在） |
| 讀取中 / 後端不可達 | 沿用探索牆的不動空位格；後端不可達自己一句 `library.off` |

**卡片狀態**（一格只顯示一個，依序取第一個成立的；計數行永遠在）：

| 狀態 | 條件 | 色塊 |
| --- | --- | --- |
| 失敗 | 這條 Route 上有 Job 在 `submit_failed` / `missing_files` / `client_error` / `import_failed` | `blocked` |
| 待審 | 有 Job 在 `review` | `assigned` |
| 下載中 | 有 Job 在 `requested` … `importing` 之間的進行中狀態（含 `stalled`） | `working` |
| 已入庫 | 電影有正片入庫；劇集每一集已播出的正片都入庫了 | 中性 |
| 部分 | 有入庫、但還有已播出的集數沒有 | 中性 |
| 沒有檔案 | 以上皆非（例如 torrent 已從客戶端移除、什麼都沒入庫） | 中性 |

**計數行**：劇集 `10 / 28 集入庫`（分母是已播出的正片集數，不含 S00）；電影 `N 個版本`（沒有正片時 `—`）。
**build 定案**：電影一個版本時寫「1 個版本」而不是本文件原本的「已入庫」——那一格的狀態色塊已經寫著
「已入庫」，計數行再說一次只是重複（code-review 的 Spec 軸指出了這個差異，決定保留實作並改這裡）。

**Jellyfin 那一行**（標識帶最下面，與上面的連結並排不巢狀）：

| 狀態 | 條件 | 樣子 |
| --- | --- | --- |
| 找到了 | 有正片的 `jellyfin_item_id`（劇集要有 Series id） | 連結「在 Jellyfin 開啟」，新分頁，名字裡說明會開新分頁 |
| 還在找 | 有正片還排著反查（`resolve_after` 有值） | 「Jellyfin 還在掃描」 |
| 找不到 | 反查用完 6 次仍沒有 | 「Jellyfin 找不到它」——詳情頁的檔案清單說得出是哪幾個 |
| 還沒入庫 | 沒有正片進帳本 | 整行不畫（計數行已經說了） |

### Media 詳情

| 狀態 | 樣子 |
| --- | --- |
| 各集「入庫」欄 | 已入庫（字）· 下載中（`working` 色塊）· 卡住（`assigned` 色塊，連到下載列表）· 缺（字）· 未播出（弱字） |
| 判定 | 已入庫 = 帳本有正片蓋到那一集；卡住 = 有 Job 停在 `review` / `import_failed` 且它的計劃蓋到那一集；下載中 = 進行中的 Job 的計劃（含預估）蓋到那一集；其餘已播出 = 缺，沒播或沒有播出日 = 未播出。**以伺服器的 UTC 日期判定播出** |
| 送單了但還沒有檔案清單 | 那幾集照樣是「缺」——還不知道那一包蓋到哪幾集；卡片上是「下載中」，說得出有東西在路上 |
| 檔案清單是空的 | 一句「還沒有任何檔案入庫」 |
| 檔案 | 依季分組的原生 `<details>`（預設全收，與季集同一個理由），電影不分組。一列：處置色塊（正片 / 特典 / 字幕，中性）· `S01E01` · Tags · 目標路徑（整條換行）· 帳本狀態 · Jellyfin（已收錄 / 還在掃描，下一次 N 後 / 找不到，試了 6 次） |
| Unmatched | 自己一組，排在最後：來源路徑 + 「留在 complete 原位，不入庫」+ 連到下載列表。資料來自這部作品各 Job 現在那一份計劃 |
| 多版本 | 只列有兩個以上版本的集（或電影）。每一組列出 Jellyfin 會顯示的**版本標籤**：電影是 ` - ` 之後的 Tags，劇集是**整個檔名主幹**（brief §7.7）；附一句「Jellyfin 版本選單的先後順序不保證」。沒有多版本時一句話，不留空區塊 |
| 帳本狀態 | M1 只會是 `ok`（其餘三種是 M2 的 Reconciler 寫的），仍照值顯示，不寫死 |

## 6. 互動與版面

- **寬度**：`max-w-[110rem]`，與探索牆同寬；390px 時切換列與篩選列換行，不橫向捲動。
- **切換列與篩選列**：`<nav>` 各自有名字；Tab 順序＝切換列 → 篩選列 → 卡片（卡片連結 → 那一格的 Jellyfin 連結）。
- **卡片**：海報 + 標題那一塊是一條連到 `/media/$id` 的 `Link`；Jellyfin 那一行是同一格裡、在它下面的另一條
  `<a>`。hover / focus 時整格邊框由 `rule` 換 `rule-strong`。標識帶高度固定到計數行為止，Jellyfin 那一行
  各格一樣高（沒有連結時留一條 `—`，基線不錯開）。
- **篩選切換**不重抓：資料一次到手，篩選在前端做（清單是幾十到幾百筆），數字由後端算。切換之後的筆數進 `aria-live`。
- **Media 詳情第 4 塊**：抬頭與第 2 塊同一種（`label` + 數字 + 重橫線）。檔案列的機器字串（路徑、Tags、`S01E01`）
  走 `.value`，換行不截斷。
- **深連結的網址**：`{對外網址}/web/#/details?id={itemId}&serverId={serverId}`（brief §20.1 實測形式）。

## 7. 約束與不可自行發明的決定

- **Jellyfin 對外網址的推導順序**（使用者拍板）：
  1. `JellyfinSettings.public_url` 有值就用它；
  2. 否則 Jellyfin 是**既有**服務 → 用它的 `base_url`（使用者自己填的，瀏覽器多半到得了）；
  3. 否則（套件內）→ 瀏覽器目前的 `protocol//hostname` + `base_url` 的 port。
  後端回前兩種的結果，或者回「用瀏覽器主機名 + 這個 port」；**第 3 步只能在前端做**，
  而且只有這一步在前端。
- **劇集深連結到 Series，電影到 Movie item。** 取不到 Series id 的劇集算「還在找」，不給一條連到某一集的連結。
- `serverId`：從反查的 `/Items` 回應取（每個 item 都帶 `ServerId`）。**實作時對 12.0.0 實測**：
  不帶也開得到的話就不存、不送。
- **卡片狀態與各集狀態的判定規則在後端，前端不重算**（`JobOut.retryable` 的同一個規矩）。
- **The One Meaning Rule**：失敗 `blocked`、待審與卡住 `assigned`、下載中 `working`；已入庫不用 `secured`。
- **i18n**：所有文案走 key，zh-Hant 與 en 並列。作品標題、季名、集名、路徑、Tags、版本標籤不是文案。
- **無障礙**：深淺兩主題文字 ≥ 4.5:1；390px 無頁面層級橫向捲動；外部連結說得出會開新分頁；
  篩選結果的筆數進 `aria-live`。
- **不可發明**：`JobState` 的分組（上表）、帳本欄位、深連結格式、Specials 不進總數、反查 6 次的上限。
