# Shape：Media 詳情頁 `/media/:id`（票 04）

`/impeccable shape Media 詳情頁`，2026-09-09。使用者拍板三個問題（整頁骨架、季集呈現、追蹤與 Route 的先後）。
這是 shape brief，不是 direction contract：實作由票 04 的 build 進行，視覺世界沿用既有的 DESIGN.md。

**這一頁會分三次長出來**：本票做身分帶與季集，票 08 往中間插搜尋結果表，票 13 再插檔案與版本清單。
所以本文件同時是後兩票的版面契約——它們往既有的區塊序列裡加一塊，不重排這一頁。

## 1. 工作與讀者

- **模式：Operate。** 讀者剛在探索牆上認出一部作品，點進來要做一個決定：**這是不是我要的那部，
  要不要交給 Berth 管，入庫到哪裡。** 表達力讓位給「決定得下去」。
- **誰來**：`admin` 與 `user` 都進得來（brief §11）。`user` 也追蹤得了、也選得了 Route——
  送單本來就是一般使用者的動作（PRODUCT.md 的角色表）。
- **從哪裡來**：探索頁的卡片（票 03 留下的那條線：卡片這一票才變成連結）。之後也會從媒體庫頁
  （票 13）與 Job 詳情進來。
- **這一頁是決策中心**（brief §13）。它不是 TMDB 的鏡子——鏡子上沒有「我追了沒」「它會落在哪個資料夾」。

## 2. 成果與證據

- **主要任務**：追蹤這部作品並指定它的 Route。成功 = `media` 有了一列、`folder_name` 凍結、
  預設 Route 指定好，畫面把這三件事說出來。
- **產品專屬的真話**（TMDB 不知道、也只有 Berth 說得出來的三件）：
  1. **追蹤狀態**——這部作品歸不歸 Berth 管。
  2. **凍結的資料夾名**——`SPY x FAMILY (2022) [tmdbid-120089]`。這是這一頁的**署名事實**：
     它是之後真的會出現在檔案系統上、而且改不掉的那一串字（plan §5、brief §4.5）。
     所以它在**按下追蹤之前**就要看得到（PRODUCT.md 原則 2：動手前先給看）。
  3. **預設 Route**——這部作品之後送單會落到哪一個媒體庫。
- **真實資料範圍**（2026-09-09 對真 `api.themoviedb.org` 實測）：
  - SPY×FAMILY（`tv:120089`）：3 季 + Specials、50 集，有 Absolute Numbering group（50 集）。
  - 名偵探柯南：TMDB 併成 **1 季 1213 集**（brief §20.3）。一季的集數沒有上限。
  - 電影（`movie:1241982`）：**完全沒有季集**，只有片長 100 分鐘。
  - 季名不一定是 `Season N`：`Specials`、`Hashira Training Arc` 這種篇章名是 plan §4.4 的季號來源，
    所以季名是**資料**不是裝飾，一定要顯示出來。
  - Absolute 排序只有大約六成的動漫有（brief §20.3），沒有的時候那一欄整個不畫。
- **法定要求**：這一頁顯示 TMDB 資料，所以頁尾要有歸屬聲明與 TMDB 標誌（brief §20.3），與探索頁同一塊。

## 3. 選定方向

- **視覺權威**：既有的 DESIGN.md「泊位調度板」，不新開世界。
- **結構論點：一張貨櫃提單。** 上方是提單抬頭——左邊一格海報（貨櫃的塗裝，與探索頁的卡片是同一塊漆），
  右邊是這批貨的識別欄位與**要簽的那一行**（Route + 追蹤）。抬頭底下用一條 `border-b-2 border-rule-strong`
  切開，再來是逐項清單，一區一疊，**每一區都是整寬**。
- **焦點時刻**：第一個 viewport 就要同時看得到「這是哪部作品」與「那顆追蹤按鈕」。海報不放大、不出血。
- **實作後果**：整寬堆疊是為了票 08 那張五欄結果表（大小 / 做種 / 來源 / Tags / 預估）與票 13 的檔案清單——
  它們在一個 5:7 的右欄裡讀不完。代價是動作列會被捲出畫面，所以窄版沿用 `STICKY_ACTION`。

## 4. 範圍與邊界

- 範圍：`/media/:id` 一頁的身分帶、季集、追蹤與 Route，以及它們的載入 / 空 / 錯誤狀態。
- **不做**：搜尋 torrent 與送單（票 08、09）、檔案與版本清單（票 13）、各集的入庫狀態
  （票 13 才有 ledger，本票的集列**不畫任何狀態欄**）、RSS 訂閱（M3）、取消追蹤（刪除範圍是 brief §9.2，M2）。
- **不碰**：AppShell 頁首、探索頁的卡牆版面（只把每一格包成連結）、設計 token。
- **反目標**：
  - 不做整寬出血的 backdrop 大圖。Seerr 那樣做，但這塊板子沒有漸層、沒有遮罩，
    而字壓在劇照上就違反 The Paint Needs A Painted Ground Rule。海報維持 2:3 的一格塗裝。
  - 不放演員、劇組、預告片、評分星等、相似作品。TMDB 有，但它們不參與「要不要追蹤、落到哪裡」這個決定。
  - 不做 tab。四個區塊是一條決策順序，把它們藏進 tab 等於要使用者先知道答案在哪一格。
  - 不做 hover 才出現的資訊（觸控裝置上不存在）；不做骨架屏動畫。

## 5. 狀態與範圍值

| 狀態 | 樣子 |
| --- | --- |
| 讀取中 | 海報格留 `well` 空位、識別欄位留兩條 `deck` 線。版面不跳，不是骨架屏動畫 |
| 未追蹤 | Route 下拉 + 黃漆「追蹤」按鈕；資料夾名以「將會是」的口吻先顯示 |
| 已追蹤 | 同一個 Route 下拉仍可改（Route 不是凍結的東西）+ `secured` 色塊「已追蹤」；資料夾名改成陳述句 |
| 追蹤中 | 按鈕文字換成進行式，不停用（票 02b 的規則：按鈕永遠按得下去） |
| 電影 | 沒有季集區塊。識別欄位改列片長，不留一個空的「0 季」 |
| 一季 1213 集 | 季列預設全收，展開才畫集表。集表本身不分頁——展開是使用者自己要的 |
| 沒有海報 | 格子留 `well` 底 + 置中 `NO ART` 模板字，與探索頁同一種處理 |
| 沒有相符的 Route | 下拉換成一句可行動的說明 + 連到精靈泊位 4（只有 admin 看得到連結，`user` 看到「請管理員…」） |
| 快照過期 | 超過 24 小時自動重抓（plan §8.3），使用者不必按任何東西 |
| 快照過期但 TMDB 連不上 | **仍然畫得出整頁**：用存下來的快照 + 一塊說明「這是 N 前的快照」。空白畫面才是最糟的 |

## 6. 互動與版面

- **身分帶**：`sm` 以上是 `grid-cols-[auto_minmax(0,1fr)]`——左邊海報固定 11rem（2:3），右邊識別欄位；
  窄版海報縮成 7rem 仍與文字並排（整寬海報會把追蹤按鈕推到第二屏）。
- **識別欄位**走既有的 `Cutaway`（`dl` 兩欄表，The Values Sit On Their Line Rule）：
  類型代號、TMDB ID、首播 / 上映、季數與集數（電影是片長）、資料夾名。
  **`TV` / `MOVIE` 與 `tmdbid` 是機器字串，走 `.value` 不走 `.label`**（The Machine String Rule）。
- **標題**：顯示用標題（`zh-TW` 那一輪）當 `h1`；英文標題與原文標題不同時各自一行在下面。
  **三個標題都要在**——英文標題是檔名用的那一個（brief §7.5），使用者要看得到它。
- **簡介**：`max-w-prose` 的散文，`zh-TW` 那一輪；沒有中文簡介時落回英文。它回答「這是不是我要的那部」。
- **動作列**：`Route: [下拉] [追蹤]` 一行。原生 `<select>`（DESIGN.md：原生優先，這裡不需要行為基礎的元件），
  只列 `collection_type` 與這部作品相符的 Route。窄版走 `STICKY_ACTION` 貼底。
- **季集**：每季一個原生 `<details>`，**預設全收**。`<summary>` 是一條纜繩列樣式的列：
  `S01`（`.value`）· 季名 · 集數 · 首播日。展開後是集表，四到五欄：
  `E01` · 集名 · 片長 · 播出日 ·（有 absolute group 時）`#38`。
  `<summary>` 已在全域焦點環的選擇器裡（DESIGN.md 記過那次補救）。
- **鍵盤**：Tab 順序＝海報略過（裝飾）→ Route → 追蹤 → 各季 summary → 頁尾連結。
  追蹤結果進 `aria-live`：整頁只有那一行文字會變，看不見畫面的人得知道按下去發生了什麼。
- **回饋**：追蹤成功後**不跳頁、不開 dialog**，就地把那一列從「將會是」換成「已追蹤」（The Failure Expands In Place 的同一個道理）。

## 7. 約束與不可自行發明的決定

- **資料夾名的模板已凍結**（plan §5、M0 票 04 的實測）：`{title} ({year}) [tmdbid-{id}]`。
  標題語言依 brief §7.5（英文 `name`，缺才落回 `original_name`）。這一頁只是把它顯示出來，不重新設計。
- **一旦追蹤就不再改 `folder_name`**（plan §5、brief §4.5）。未追蹤的列上它是預覽，追蹤那一刻凍結。
- **季名與 absolute 排序是資料不是裝飾**（plan §4.4）：季名是解析器的季號來源，absolute 是動漫釋出的編號習慣。
  兩者都顯示原文，不翻譯、不美化。
- **不可發明**：快照壽命（24 小時，plan §8.3）、海報尺寸（`w342`）、`media.id` 的形狀（`tv:` / `movie:`）、
  Route 的 `collection_type` 比對規則、TMDB 歸屬聲明。
- **這一頁不出現四個信號色中的任何一個當作狀態**，除了錯誤 `TmdbNotice` 的 `blocked`，以及
  「已追蹤」——它沿用探索頁的**中性色塊**（The Role Is Not A State Rule：追蹤是一段關係，不是健康狀態）。
- **i18n**：所有文案走 key，zh-Hant 與 en 並列。**作品標題、季名、集名不是文案**——它們來自 TMDB，原樣顯示。
- **無障礙**：深淺兩主題所有文字 ≥ 4.5:1；390px 無頁面層級橫向捲動；集表過寬時由它自己的容器捲動，不是整頁。

## 8. 開放但由 build 決定（已於 build 定案）

- **絕對編號那一欄放在集號旁邊，不是最後一欄**，推翻 §6 寫的 `E01 · 集名 · 片長 · 播出日 · #38`。
  理由是 `E01` 與 `#26` 是同一件事的兩種編號（這一集是誰），而片長與播出日是它的屬性；
  兩個編號分站兩端時，動漫使用者要在一行裡跳著看才對得起來——而他正是為了那一欄來的。
- **快照新鮮度那一行住在身分帶裡**，不是自己一個區塊。§3 的區塊序列只有五塊，而第三塊是
  票 08 的搜尋結果表；在那裡多長一塊出來，後面兩票就得重排這一頁（code review 抓到的）。
- **季數與集數不含 Specials。** TMDB 自己的 `number_of_seasons` / `number_of_episodes` 也不含
  （SPY×FAMILY 是 3 季 50 集，不是 4 季 53 集），而封面上印的就是那個數字。季集**清單**仍然
  列出 S00——那一季是真的存在，只是不進總數。
- **快照過期用 `assigned` 不用 `blocked`。** 紅色只代表「在你動手之前走不下去」，而這一格的前提
  正是頁面照樣畫得出來（The One Meaning Rule）；順帶讓掉 `blocked` 會帶的 `role="alert"`。
- **`sanitize` 這一票就要做完**（plan §5 的完整規則），不是留給票 07。理由是 `folder_name` 在
  追蹤那一刻**凍結進資料庫**：`Mission: Impossible` 現在被寫成非法路徑的話，票 07 補規則時
  那幾列已經改不掉了。票 07 接手其餘五種模板，共用同一支。
