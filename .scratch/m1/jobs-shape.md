# Shape：下載列表頁 `/jobs`（票 09）

`/impeccable shape`，2026-09-10。Berth 的第五個 UI 面。視覺世界沿用 DESIGN.md「泊位調度板」，不新開世界。

使用者拍板三件事：**時間線在列內就地展開**（不另建 `/jobs/:hash`）；**進度那一欄現在就畫，沒有值就說沒有值**；
**純粹最新在前**，不分組也不把失敗置頂。

## 1. 工作與讀者

- **模式：Operate。** 讀者剛在 Media 詳情頁按下送單，或者是隔天回來看昨天送的那幾筆。
  這一頁要回答的是：**我送出去的東西怎麼樣了；有沒有哪一筆卡住了要我處理。**
- **誰來**：`admin` 與 `user` 都進得來（brief §11）。送單本來就是一般使用者做的事，而這是他送單之後去的地方。
- **這一頁不是儀表板。** 使用者不會整天盯著它（PRODUCT.md「維運儀式」）——他在兩個時刻打開它：
  剛按完送單想確認真的進去了，以及「怎麼那部片還沒出現在 Jellyfin」。兩個時刻要的都是**逐筆的狀態與理由**，
  不是總量統計、不是折線圖。

## 2. 成果與證據

- **主要任務**：一眼看出哪幾筆有問題；對有問題的那一筆，讀得出理由並按得下重試。
- **產品專屬的真話**（qBittorrent 自己的介面說不出來的三件）：
  1. **這一筆是哪一部作品、要進哪一條 Route。** qBittorrent 只知道一個 category 字串。
  2. **是誰、用什麼方式送的**（`trigger` / `user_name`）。M3 起同一份清單裡會混著 RSS 規則自動送的。
  3. **送單失敗的原文與下一步。** qBittorrent 上根本不會有那一筆——它從來沒被收下（PRODUCT 原則 4）。
- **真實資料範圍**：
  - **M1 票 09 只走得到三個狀態**：`requested`、`submitted`、`submit_failed`（plan §3.1）。
    其餘十三個由票 10 起的迴圈驅動，但狀態字典一次定義完（`domain.JobState`）。
  - 發佈名與搜尋結果表同一批字串：41 字到 100+ 字，中日英混排（票 08 實測）。**不截斷**，理由同票 08 §8。
  - `progress` 與 `total_size` 在這一票**永遠是 0**：qBittorrent 報得出它們要等票 10 的 poller。
  - 筆數：個位數到幾十筆。使用者手動送單的節奏就是這樣，M3 的 RSS 才會讓它長到上百。
  - `hash` 是 40 字十六進位。畫面上顯示**前 12 字**就夠認人，整串在 `title` 與可複製的那一列裡。

## 3. 選定方向

- **視覺權威**：DESIGN.md「泊位調度板」。這一頁沿用面板（`well` 底 + `deck` 抬頭列 + `border-2`）、
  信號色塊（狀態）、中性色塊（trigger）、纜繩列（時間線的每一筆）與 `Timestamp`。
- **結構論點：一份船期表。** 每一筆 Job 是一列，左邊一塊漆說它現在在哪一站，右邊是實測值。
  **展開的是同一列，不是另一頁**——`<details>` 就地展開時間線（The Failure Expands In Place Rule）。
  這與健康頁的纜繩列是同一種東西：一列問「還繫著嗎」，展開問「當時發生了什麼」。
- **焦點時刻**：送單失敗那一列。整列邊框換 `rule-strong`，狀態塊是 `blocked`，
  下方就地展開服務回的原文與一顆「重試」——**不跳頁、不開 dialog、其他列不動**。
- **實作後果**：一份 DOM 兩種版面（同票 08）：`sm` 以上實測值分欄靠右，以下塌成中點分隔行。
  `<details>`／`<summary>` 是原生的（DESIGN.md：原生優先；全域焦點環已涵蓋 `summary`）。

## 4. 範圍與邊界

- 範圍：清單、逐列狀態與實測值、就地展開的時間線、重試、空狀態、載入中、後端不可達。
- **不做**：
  - `/jobs/:hash` 獨立頁（plan §7 保留給 T1.7 的完整 Job 詳情：檔案清單、Plan、刪除範圍）。
  - 刪除 Job（`DELETE /jobs/{hash}` 的四個旗標是 M2 的刪除範圍，brief §9.2）。
  - 篩選、搜尋、分頁、分組。M1 的筆數還撐得住一份平清單；M3 的 RSS 進來時再談。
  - 進度條動畫、輪詢與 SSE（票 10 的 `qbit_poller` 與 `GET /events/stream`）。**這一頁這一票是靜態的**：
    重新整理才會變。
  - 統計數字（總下載量、成功率）。使用者要的是逐筆，不是總量。
- **不碰**：頁首、泊位板、探索頁、Media 詳情頁的既有區塊、設計 token。
- **反目標**：
  - 不做把失敗置頂的排序。同一筆 Job 會在重試成功之後跳位置，而使用者剛剛才在那個位置按過按鈕。
  - 不用進度條當主要訊號。這一票的進度永遠是 0，而一整欄的空條讀起來像「全都卡住了」。
  - 不把 `client_state`（`stalledDL` 這種）翻譯成中文。它是 qBittorrent 的機器字串，
    使用者要拿它去 qBittorrent 的介面上對照（The Machine String Rule）。
  - 不做「全部重試」的批次鍵。重試會真的再打一次索引站與 qBittorrent，那不是一顆該手滑按到的按鈕。

## 5. 狀態與範圍值

| 狀態 | 樣子 |
| --- | --- |
| 空（一筆都沒有） | 一句「還沒有送過任何下載」+ 一條回探索頁的 ghost 連結。**不是錯誤**，是新使用者的正常畫面 |
| 載入中 | 沿用既有的骨架（不動的方塊，DESIGN.md：沒有動畫） |
| 後端不可達 | 沿用 `discover.off` 那一句 |
| `requested` | `working` 藍漆 + `.label` 狀態字。「已建立，還沒收到回應」——這一票裡它是一瞬間的過渡 |
| `submitted` | `secured` 綠漆。qBittorrent 收下了 |
| `submit_failed` | `blocked` 紅漆 + 整列 `border-rule-strong` + 就地展開原文 + 「重試」鍵 |
| 票 10 起的其餘狀態 | 狀態字典一次定義完（`domain.JobState` 十六個），色彩映射也一次定義完，畫面不必為它們改 |
| 進度未知 | 那一格是 `—`（票 04 的同一條：欄位不省略，省略會讓整份剖面的基線錯開） |
| 大小未知 | 同上，`—` |
| 沒有 Media（M2 的重新入庫） | 作品那一格是 `—`，不是空白 |
| 時間線 | 最舊在前。每一筆是「型別 + 時間 + 那一型別自己的那幾格」（`payload`） |

## 6. 互動與版面

- **頁面**：`max-w-[80rem]` 置中（與 Media 詳情頁同一個寬度），`px-6 py-8`。
- **抬頭列**：面板抬頭（`deck` 底 + `.label`）左邊是「下載」，右邊是筆數。與搜尋結果表同一種抬頭。
- **一列（`sm` 以上）**：`<details>` 包住。`<summary>` 是整列：
  `[狀態塊] 發佈名（換行，不截斷）` 第一行；第二行 `作品 · Route · trigger · 大小 · 進度 · 時間`。
  實測值走 `.value text-xs` 且 `tabular-nums`（The Tabular Rule）。
- **一列（`sm` 以下）**：同一份 DOM，第二行的那幾格改成中點分隔、允許換行。**不橫向捲動**。
- **展開**：`hull` 底的一塊，內縮一階。時間線每一筆一行：
  `[型別]`（中性色塊，`.label`）+ 相對時間 + `payload` 裡那一型別的那幾格（`.value text-xs`，`break-words`）。
  `submit_failed` 那一筆的 `error` 用 `blocked-ink`，並在時間線下方給那顆「重試」。
- **重試**：`GhostButton`，就在展開區裡（不是列上——列上一顆按鈕會讓整列的點擊目標打架）。
  按下去之後按鈕文字換成進行式，**不停用**（票 02b 的規則：按鈕永遠按得下去）。
- **hash**：展開區裡一列 `CopyLine`——它是使用者拿去 qBittorrent 介面上比對的那一串字。
- **作品那一格是連結**：連到 `/media/{media_id}`。這是這一頁唯一的導航出口。
- **鍵盤**：Tab 順序＝每一列的 `summary` → 展開後的作品連結 → 複製鍵 → 重試。
  `<details>` 的原生開合就是 Enter / Space。
- **`aria-live`**：重試的結果要宣告（狀態變了，而畫面上動的只有那一小塊）。

## 7. 約束與不可自行發明的決定

- **狀態的色彩映射**（The One Meaning Rule）：`requested` / `downloading` / `planning` / `importing` → `working`；
  `submitted` / `metadata_ready` / `completed` / `imported` → `secured`；
  `submit_failed` / `missing_files` / `client_error` / `import_failed` → `blocked`；
  `review` / `stalled` → `assigned`（需要你）；`client_removed` / `removed` → `neutral`。
  **紅色只代表阻擋**，所以 `stalled`（還可能自己恢復）不是紅的。
- **三重編碼**：色塊 + `.label` 狀態字 + 位置（時間排序）。灰階測試要過。
- **不可發明**：`JobState` 的十六個值（`domain/enums.py`）、`EventType` 的四個值、
  重試的語意（`submit_failed` → `requested`，plan §3.1）、拒絕的理由集合（`api/jobs.py` 的 `_STATUS`）。
- **i18n**：所有文案走 key，zh-Hant 與 en 並列。**發佈名、hash、路徑、category、`client_state`
  不是文案**——它們是機器字串，原樣顯示（The Machine String Rule）。
- **無障礙**：深淺兩主題所有文字 ≥ 4.5:1；390px 無頁面層級橫向捲動；`summary` 的焦點環由全域選擇器涵蓋。

## 8. 開放但由 build 決定（已於 build 定案）

- 時間線 `payload` 逐型別要顯示哪幾格。四個型別各自的那幾格在 `services/jobs.py` 寫死，
  畫面照型別挑——**不做一個通用的 key/value 傾印**，那會把 `trigger: manual` 這種已經在列上的東西再說一次。
- 送單確認（票 04b、plan §5、brief §4.5 的「印出資料夾名」）不在這一頁，它在 Media 詳情頁的結果表那一列。
  這一頁只承接結果。
- **實測值那一行在每個寬度都是中點分隔**，不做 §3 提過的「`sm` 以上分欄靠右」。§6 本來就
  只描述了一種（`[狀態塊] 發佈名` + 一行 `作品 · Route · trigger · …`），而實跑之後那一行
  在 1440px 與 390px 上都讀得完——分欄要的是欄頭，而這一頁沒有欄頭。§3 那半句已作廢。
- **每一格自己帶標籤**（`大小 —` / `進度 —`），§6 只寫了「靠右且 `tabular-nums`」。
  這一列沒有欄頭，而大小與進度在票 10 之前都是 `—`——不帶標籤的話那兩條破折號說不出
  自己少了什麼（票 08 窄版做種欄的同一條）。1440px 實跑量到的。
- **後端不可達沿用不了 `discover.off`**（§5 那一句作廢）：那一句說的是「讀不到 Berth 後端」，
  而這一頁要說的是「讀不到下載列表」。搜尋區塊早就有自己的 `search.off`，逐面各一句是
  這個 repo 既有的做法。
- **hash 那一格帶 `title`**（§2 寫的「整串在 `title` 與可複製的那一列裡」）：`shortHash` 只有
  前 12 字，整串在 `title` 與展開區的 `CopyLine`。
