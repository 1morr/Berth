# Shape：搜尋 torrent 與結果表（票 08）

`/impeccable shape`，2026-09-10。Media 詳情頁區塊序列的**第 3 塊**
（`.scratch/m1/media-detail-shape.md` §3 的契約）。視覺世界沿用 DESIGN.md「泊位調度板」，不新開世界。

使用者拍板三件事：搜尋是**待命、按了才搜**；窄版**改成堆疊列**不是橫向捲動；Route 下拉**從身分帶搬進搜尋區塊**。

## 1. 工作與讀者

- **模式：Operate。** 讀者已經確認這是他要的作品（第 1、2 塊回答完了），現在要挑一個 torrent。
  這一區塊要回答的是：**這一堆發佈裡，哪一個是我要的那一集 / 那一季，而且下得動。**
- **誰來**：`admin` 與 `user` 都進得來（brief §11）。搜尋不是管理動作。
- **這是使用者第一次看見解析器的判斷。** 每一列的 Tags 與預估季集就是 Berth 之後會怎麼命名這個檔案的
  預告。判斷錯了要在這裡看得出來，而不是等入庫之後才發現。

## 2. 成果與證據

- **主要任務**：搜到結果、看懂每一列、挑出一個（送單是票 09）。
- **產品專屬的真話**（索引站自己說不出來的三件）：
  1. **解析出的 Tags**——`[WEB][1080p][CHT][ANi]`，與之後真的會進檔名的那一串是同一份資料（brief §6.8）。
  2. **預估季集**——`S03 全季` / `S03E13` / 判斷不出來。TMDB 的季集對照過的結果，不是檔名的複述。
  3. **逐個查詢的成敗**——Berth 拿哪幾個名字去問、哪一個問不動。索引站的介面上沒有這個。
- **真實資料範圍**（2026-09-10 對真 Prowlarr 2.5.2 + 五個公開站實測）：
  - 一次搜尋去重後 **1726–1854 筆**，送到畫面的是 **100 筆**（逐站輪流取）；總數要說出來。
  - 一次搜尋 **35–85 秒**。三個查詢併發共 35 秒，單一冷查詢 60–85 秒。
  - 發佈名長度差距極大：`Moana 2 (2024) 1080p WEBRip 5.1 x264 -YTS`（41 字）到
    `[jibaketa合成][代理商粵語]SPY×FAMILY間諜家家酒 / 间谍过家家Season 3 - 13 END [粵日雙語+內封繁體中文字幕](WEB 1920x1080 AVC AACx2 MKV)`（100+ 字，中日英混排）。
  - 做種數常常是 **0 或 1**（公開站的舊發佈），也有 **null**（那個站沒報）。兩者不同。
  - 有的站不報 info hash（ACG.RIP），有的報 base32（dmhy）。畫面不顯示 hash，但它是每一列的身分。

## 3. 選定方向

- **視覺權威**：DESIGN.md「泊位調度板」。這一區塊沿用面板（`well` 底 + `deck` 抬頭列 + `border-2`）、
  纜繩列（逐查詢的成敗）與中性色塊（Tags）。
- **結構論點：一張裝船清單。** 抬頭列是「搜尋」這個動作本身（關鍵字欄 + Route 下拉 + 黃漆搜尋鍵），
  底下是逐筆的貨。桌機是真表格，窄版每一筆塌成一張整寬的列——**發佈名整行換行不截斷**
  （The Values Sit On Their Line Rule 的同一個道理：被切掉的發佈名等於沒顯示）。
- **焦點時刻**：按下搜尋之後，逐條纜繩亮起來說「正在問這幾個名字」。這是署名互動「靠泊序列」的
  同一種東西——不是 spinner，是逐個關鍵字的實際結果數。
- **實作後果**：整寬堆疊（票 04 已經為它讓出版面）。表格外不包 `overflow-x`——窄版根本不是表格。

## 4. 範圍與邊界

- 範圍：搜尋觸發、關鍵字欄、Route 下拉、逐查詢纜繩、結果表（五欄 + 排序）、五種 problem 的說明、
  空結果、載入中。
- **不做**：選一列之後的送單（票 09 的按鈕插在每一列右側或列上，這一票只留位置不畫）、
  檔案清單與版本（票 13）、RSS（M3）、結果快取、分頁（前 100 筆之外要更多就自己打關鍵字）。
- **不碰**：身分帶的海報、標題、識別欄位；季集區塊；TMDB 歸屬頁尾；設計 token。
- **會動到身分帶的一件事**（使用者 2026-09-10 拍板，推翻 media-detail shape §3 的「不動身分帶」）：
  **Route 下拉從身分帶搬進搜尋區塊。** 理由是它現在真的驅動一件事（查詢變體），留在上面
  等於一個沒有動作的控制項。（票 14e 起查詢不看它，它驅動的是結果表裡的送單，位置不變。）身分帶其餘部分不動，區塊序列不變。
- **反目標**：
  - 不做進頁面就自動搜。那會替每個只想看季集表的人對五個公開站發五輪查詢。
  - 不做 spinner、不做骨架屏動畫（DESIGN.md：沒有轉場、沒有動畫類別）。
  - 不做把結果表藏進 tab 或摺疊——它是這一頁的第三個決策步驟，不是附錄。
  - 不做「品質最好的自動選中」。挑哪一個是使用者的決定（PRODUCT 原則 2、3）。
  - 不用信號色表達 Tags 或來源站。它們是分類不是狀態（The Role Is Not A State Rule）。

## 5. 狀態與範圍值

| 狀態 | 樣子 |
| --- | --- |
| 待命（預設） | 關鍵字欄（留空 = 用作品的各個名字）+ Route 下拉 + 黃漆「搜尋」。底下一句話列出**會送出去的那幾個關鍵字**，以及「這會花約一分鐘」 |
| 搜尋中 | 按鈕文字換成進行式、不停用（票 02b 的規則）。纜繩區先畫出那幾個關鍵字、狀態是 `working` |
| 有結果 | 抬頭列右側「共 1726 筆 · 逐站取了 100 筆」；纜繩逐條收成 `ok` + 該關鍵字的筆數 |
| 部分失敗 | 垮掉的那一條纜繩是 `blocked` + 服務原文，其餘照樣是 `ok`；表格照畫（The Failure Expands In Place） |
| 空結果 | 「這幾個關鍵字在你的索引站上沒有東西」+ 建議自己打字。**不是**錯誤 |
| 索引站未設定 | 一句可行動的說明 + 連到精靈泊位 3（`admin`），`user` 看到「請管理員…」。**不是空清單**（票 08 驗收） |
| 憑證被拒 / 連不上 / 端點不提供搜尋 | 各自一句話與各自的下一步，形狀與 `TmdbNotice` 同一種 |
| 沒有做種數 | 顯示 `—`，不顯示 0。排序時排在 0 後面 |
| 判斷不出來 | 預估那一格是一句「判斷不出來」，不是空白也不是猜的數字 |
| 這部作品的快照還沒抓到 | 第五種 `IndexerProblem`（`no_query`）：一個關鍵字都湊不出來。它是 TMDB 那邊的事，所以它是唯一**不**連到精靈第 5 步的那一種 |
| 電影 | 預估那一格是「電影」（`MappingStrategy.MOVIE`），不是空的季集 |

## 6. 互動與版面

- **抬頭列**：面板抬頭（`deck` 底 + `.label`）左邊是區塊名，右邊是筆數。`sm` 以下筆數換行到第二行。
- **搜尋列**：`關鍵字 [____________] Route [▾] [搜尋]`。`lg` 以上一行，以下疊成三行。
  原生 `<input>` 與 `<select>`（DESIGN.md：原生優先）。Enter 送出（整列包在 `<form>` 裡）。
- **關鍵字預覽**：搜尋列底下一行 `.value text-xs`，列出實際會送出去的關鍵字，逗號分隔。
  它是 PRODUCT 原則 2（動手前先給看）在這一區塊的形式。
- **纜繩區**：沿用 `StepLine`。`step` 是關鍵字本身（機器字串，走 `.value`），`detail` 是筆數。
- **結果表（`sm` 以上）**：`<table>`，五欄。發佈名欄 `minmax(0,1fr)`，其餘四欄由內容決定寬度。
  第一行是發佈名（`.value`，`break-words`；**不截斷**，見 §8），第二行是 Tags 色塊列。
  大小 / 做種 / 預估三欄靠右且 `tabular-nums`（The Tabular Rule）。
- **結果列（`sm` 以下）**：整寬的列，`border-b`。第一行發佈名（不截斷），第二行 Tags 色塊，
  第三行是 `500 MB · 做種 42 · ACG.RIP · S03E13` 的中點分隔行（`.value text-xs`）。
  做種那一格帶標籤：窄版沒有欄頭，光一個數字說不出它是什麼。
- **排序**：欄頭是按鈕，做種與大小可排（`aria-sort`）。預設做種由多到少。窄版沒有欄頭，
  所以排序在搜尋列旁邊給一個 `<select>`（做種 / 大小）。
- **來源站連結**：來源那一格是連到 `info_url` 的外部連結（`target="_blank" rel="noreferrer"`）。
  沒有 `info_url` 的站就只是文字。
- **鍵盤**：Tab 順序＝關鍵字 → Route → 搜尋 → 排序 → 各欄頭 → 各列的來源連結。
- **`aria-live`**：搜尋結束時宣告「找到 N 筆，其中 M 個關鍵字失敗」。看不見畫面的人得知道按下去發生了什麼。

## 7. 約束與不可自行發明的決定

- **五欄就是 brief §13 列的那五樣**：大小、做種、來源、解析出的 tags、預估匹配。不加不減。
- **Tags 的呈現是結構化欄位逐格畫，不是 `Tags.render()` 那一串字**——但畫出來的內容要與那一串字
  一致（brief §6.8 是唯一的詞彙表）。
- **不可發明**：預估的說法（見 §8 的第四種）、`route` 的語意（送單用的偏好，不是承諾，票 04b；票 14e 起搜尋不帶它）、
  筆數上限 100、五種 `IndexerProblem` 的下一步。
- **i18n**：所有文案走 key，zh-Hant 與 en 並列。**發佈名、站名、Tags token 不是文案**——
  它們來自索引站與 brief §6.8 的詞彙表，原樣顯示。
- **無障礙**：深淺兩主題所有文字 ≥ 4.5:1；390px 無頁面層級橫向捲動；欄頭排序按鈕帶 `aria-sort`。

## 8. 開放但由 build 決定（已於 build 定案）

- **發佈名不截斷**，推翻 §6 的「最多兩行後省略」。它是這一列的**證據**——解析器讀的就是同一串字，
  而 Tags 與預估是它的判斷。截掉之後使用者沒辦法自己看出「為什麼判成 S03E13」。
  實跑最長的一筆是 100 字（中日英混排），桌機兩行、390px 三行，都還在一屏之內。
- **預估有第四種說法：`S03` 單獨出現**（知道季、說不出集）。§7 原本只准三種。留著是因為丟掉季號
  比留著糟——「第三季，但看不出是哪一集」是一句真話。實務上很少見：`map_episode` 只在算得出集號
  時才產出候選，所以這一格是防守用的。
- **「逐站成敗」實作成「逐查詢成敗」。** 票的字面是逐站，但 Prowlarr 的 `GET /api/v1/search`
  聚合完就回，**不報逐站的成敗**（2026-09-10 查證），所以那個粒度拿不到。Berth 看得見的單位是
  「一個關鍵字一次請求」，纜繩畫的就是它。單一 Torznab 端點時兩者本來就是同一件事。
- **搜尋中先鋪出 `working` 的纜繩**（§5 的「搜尋中」那一列）。一次搜尋 35–85 秒，只有按鈕文字變
  「搜尋中…」的話畫面看起來像當掉了。
