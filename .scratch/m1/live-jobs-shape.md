# Shape：會自己動的下載列表 + 健康頁的下載迴圈（票 10）

`/impeccable shape`，2026-09-10。**兩個既有頁面的增補**，不是新頁面：視覺世界沿用 DESIGN.md
「泊位調度板」，`/jobs` 的結構沿用 `.scratch/m1/jobs-shape.md`，健康頁沿用它的纜繩列與剖面。

使用者拍板兩件事：**不做「即時」指示器**（值自己跳就是最誠實的訊號）；**無主 torrent 畫在健康頁**
的下載迴圈區塊，不進下載列表。

## 1. 工作與讀者

- **模式：Operate。** 兩個時刻：剛按完送單、盯著那一列想知道「進去了嗎」；以及隔天回來問
  「怎麼那部片還沒出現在 Jellyfin」。第一個時刻是這一票新增的——票 09 交出去的那一頁是靜態的，
  使用者得自己按 F5 才看得到狀態換。
- 健康頁的讀者是同一個人，但問的是另一個問題：**整條線還動得了嗎**。三個服務都綠著、
  而下載列表整片停住，是這一票之前看不出來的一種壞法。

## 2. 成果與證據

- **主要任務**：不重整就看得完「送出 → 拿到檔案清單 → 下載 → 完成」，並在卡住時讀得出理由。
- **產品專屬的真話**（qBittorrent 自己的介面說不出來的）：時間線把「Berth 什麼時候知道了什麼」
  排成一行——`metadata_received` 說它拿到幾個檔案、`progress` 每跨 25% 一筆、`issue_detected`
  說它為什麼停下來。qBittorrent 只有一個當下的百分比。
- **真實資料範圍**：進度 0–1（票 09 之前永遠是 0，現在是真的）；一筆 Job 的時間線 2–12 筆事件
  （4 筆狀態 + 最多 3 筆進度 + 收尾）；無主 torrent 平常 0 筆，資料庫還原之後可能十幾筆。

## 3. 選定方向

- **不加任何「即時」的裝飾。** 沒有指示器、沒有脈動點、沒有轉場——DESIGN.md 的「動態」段寫著
  這塊板沒有動畫也沒有 spinner。值自己換就是訊號本身。斷線由瀏覽器的 `EventSource` 自己重連，
  重連時 TanStack Query 會重問一次，所以使用者不需要知道中間斷過。
- **推播是提示不是真相。** SSE 只帶 hash / state / progress，前端據此讓 `['jobs']` 失效再問一次。
  漏掉一筆的後果因此是慢一點，不是畫面說謊。
- **時間線的五種新事件沿用既有的一行三段**（型別中性色塊 + 相對時間 + 那一型別自己的那幾格）。
  `issue_detected` 的 `type` 走 `blocked-ink` 的一句字，**不是**紅色塊——那一列的狀態格已經是紅的了
  （The One Meaning Rule：同一件事不塗兩次漆）。
- **健康頁的「下載迴圈」是一個剖面加一份清單**，不是第五個泊位格。泊位板永遠四格
  （The Board Never Scrolls Rule），而迴圈不是一個「接上了沒」的服務。

## 4. 範圍與邊界

- 範圍：`/jobs` 的 SSE 訂閱與失效、時間線五種新事件、進度那一格的真值；健康頁新增一個
  「下載迴圈」區塊（上次輪詢、輪詢間隔、連續失敗與原文、無主 torrent 清單）。
- **不做**：進度條（shape brief 票 09 §4 的反目標仍然成立——一整欄的空條讀起來像「全都卡住了」）、
  即時指示器、`/jobs/:hash` 獨立頁、無主 torrent 的處置動作（`issues` 表在 M2）。
- **不碰**：泊位板、頁首、四項服務檢查、Route 纜繩列、設計 token。
- **反目標**：不把 `client_state`（`stalledDL`）翻成中文（The Machine String Rule）；
  不因為「有新事件」而讓那一列閃一下——閃爍會讓一份 40 列的清單在下載尖峰時整片抖動。

## 5. 狀態與範圍值

| 狀態 | 樣子 |
| --- | --- |
| SSE 連不上 | **畫面不變**。清單仍然畫得出來（它是 `GET /jobs` 的結果），只是不會自己動 |
| 進度未知 | 那一格仍是 `—`（票 09 的同一條），有值才是百分比 |
| 迴圈從來沒跑過 | 「上次輪詢」是「沒有紀錄」（`Timestamp` 的既有說法），不是「尚未檢查」 |
| 迴圈連續失敗 | 剖面那一列換 `blocked-ink` 的次數與原文；區塊邊框換 `rule-strong`（線變重，不是變紅） |
| 無主 torrent 0 筆 | **整個清單不畫**，只留剖面三行。0 是正常，不是一個要人看的數字 |
| 無主 torrent N 筆 | 一列一筆：`client_state` 中性色塊 + 發佈名（換行不截斷）+ category · 短 hash |

## 6. 互動與版面

- `/jobs`：`useJobStream()` 掛在頁面上（不是 AppShell——只有這一頁在乎），收到訊號就
  `invalidateQueries(['jobs'])`；展開中的那一列另外失效它自己的 `['jobs', hash, 'events']`。
- 時間線每一筆維持 `[型別] 相對時間` + 那一型別的那幾格：
  `metadata_received` → 檔案數與總大小；`progress` → 百分比（恢復時另加一句「又動起來了」）；
  `stalled` → `client_state` 與停了幾分鐘；`completed` → 總大小；`issue_detected` → 逐種一句話。
- 健康頁：新區塊排在四項服務之後、Route 清單之前——它問的是「Berth 自己的迴圈」，
  比 Route 的五條纜繩上游。剖面用既有的 `Cutaway` / `CutawayRow`。
- 窄版（390px）：剖面塌成單欄；無主 torrent 那一列的三格中點分隔、允許換行，不橫向捲動。
- `aria-live`：**不加**。清單自己更新時加 live region 會讓螢幕閱讀器在下載尖峰時不停說話；
  這一頁是唯讀的掃視面，使用者是主動來看的。重試那一顆按鈕的既有 `aria-live` 不動。

## 7. 約束與不可自行發明的決定

- **事件型別是後端的封閉集合**（`domain.EventType` 九種、`domain.IssueType` 四種）。前端窮舉，
  認不得的型別只畫色塊與時間——不印 i18n key。
- **SSE 的形狀**：`event: job` + `data: {hash, state, progress}`（`services/events.py`）。
- **i18n**：所有文案走 key，zh-Hant 與 en 並列。發佈名、hash、category、`client_state` 是機器字串。
- **無障礙**：深淺兩主題所有文字 ≥ 4.5:1；390px 無頁面層級橫向捲動；純鍵盤可完成。
