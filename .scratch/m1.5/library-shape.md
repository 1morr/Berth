# Shape：媒體庫頁 `/library/:libraryId`——一個 Jellyfin 媒體庫一頁（M1.5 票 03）

`/impeccable shape`，2026-09-17。視覺世界沿用 DESIGN.md「泊位調度板」，不新開世界。取代
`.scratch/m1/library-shape.md`（票 13 的一條 Route 一頁）的頁面序列與範圍；卡片的狀態判定、色塊與
Jellyfin 那一行的語彙沿用它。

使用者拍板三件事（2026-09-17）：

1. **Jellyfin 裡還沒有的作品放在牆上方一條帶子**，只在有這種作品時出現、不分頁，翻到第幾頁都看得到；
   下面才是 Jellyfin 的分頁牆。
2. **「待審」「Unmatched」篩選換成 Berth 那一份清單**：篩選時整面牆換成這個媒體庫裡被標記的作品（在 Jellyfin
   裡的與還沒進的都算），不分頁；「全部」回到 Jellyfin 的分頁牆。
3. **分頁沿用 Jellyfin Web**：每頁 100 部、「1–100 / 523」加上一頁 / 下一頁，頁碼在網址上。

拆票時已定的（票面）：牆上已在 Jellyfin 裡的作品顯示 Jellyfin 的名稱；有 TMDB id 的連 `/media/:id`，沒有的只給
Jellyfin 深連結；海報是票 04。

## 1. 工作與讀者

- **模式：Operate。** `admin` 與 `user` 都進得來；看到的是**自己在 Jellyfin 看得到**的電影與劇集媒體庫。
- **兩個時刻**（與票 13 相同）：「我想看那部片」——在整個媒體庫裡認出作品，到 Jellyfin 播或進詳情；
  「怎麼那部還沒好」——Berth 經手的作品裡哪一部需要人、哪一部還沒進 Jellyfin。
- **變的是範圍**：牆上不再只是 Berth 經手的作品，而是整個 Jellyfin 媒體庫；Berth 的入庫狀態是疊上去的一層。

## 2. 成果與證據

- **主要任務**：翻得到這個媒體庫的每一部作品；Berth 經手的那幾部一眼看得出狀態。
- **只有 Berth 說得出來的真話**：
  1. Jellyfin 牆上哪幾部是 Berth 經手的、入庫了幾集、哪一部需要你（票 13 的判定，換成依媒體庫彙整）。
  2. **Berth 經手、但 Jellyfin 還沒有的作品**——下載中、待審、失敗、Jellyfin 還在掃描。Jellyfin 自己看不到它們。
  3. **這位使用者看不到的媒體庫不存在**：切換列、篩選數字、帶子上的卡片都不透出任何一個無權媒體庫的東西。
- **真實資料範圍**：
  - 一位使用者的 `UserViews` 有 0 到十來個媒體庫，只列 `movies` 與 `tvshows` 兩種（音樂、書、`mixed`、
    `homevideos`、播放清單都不列）。
  - 一個媒體庫 0 到數千部作品；Berth 經手的 0 到數百部；Jellyfin 還沒有的通常是個位數到數十部。
  - Jellyfin 的名稱是一種語言（伺服器的 metadata 語言），可能與 UI 語言不同；有的作品沒有 TMDB id。

## 3. 選定方向

- **視覺權威**：DESIGN.md。卡片沿用 `InventoryTile` / `MediaTile` 的貨櫃語彙與 `WALL_GRID`（2 / 3 / 4 / 6 欄）。
- **結構論點：堆場全景加一條待卸貨的碼頭邊。** Jellyfin 的牆是已經進倉的整座堆場（一頁 100 箱，照 Jellyfin 的
  編號順序）；牆上方那一條是還停在碼頭邊、還沒進倉的貨。兩者用同一種貨櫃，差別在位置與標識帶最下面那一行。
- **頁面序列**：抬頭（`媒體庫`）→ 媒體庫切換列 →〔票 07：這個媒體庫的繼續觀看、下一集〕→「還沒進 Jellyfin」帶
  → 篩選列（左）與分頁（右）→ 牆 → 底部分頁 → TMDB 標示。
  - **切換列**：一排連結方塊，每個媒體庫自己一個網址，**只有名稱**（`UserViews` 沒有可靠的作品數，總數移到牆上方
    那一行）。順序照 `UserViews`——那是使用者在 Jellyfin 自己排的。
  - **「還沒進 Jellyfin」帶**：`.label` 標題 + 數字，壓在重橫線上；同一份 `WALL_GRID`。標題不叫「在路上」：失敗、
    Jellyfin 找不到的也在這裡，它們不是在路上。沒有這種作品時整條不畫，也不留空標題。
  - **篩選列**：`全部` · `待審 N` · `Unmatched N`，數字是這個媒體庫裡 Berth 經手作品的總數（跨 Jellyfin 內外）。
  - **分頁**：`1–100 / 523` + Ghost「上一頁」「下一頁」。上方一組貼在篩選列右邊，牆底一組。
- **焦點時刻**：一整面 Jellyfin 牆幾乎全是中性的；只有 Berth 經手、需要人的那幾格塗漆
  （The Usual Stays Unpainted Rule）。沒有 Berth 經手的作品連中性色塊都沒有——它不是一種狀態。
- **實作後果**：「這一部在不在 Jellyfin」「連到哪裡」「需不需要人」全部由後端算好，前端只照畫。權限閘門在
  services，前端不知道使用者的 Jellyfin id。

## 4. 範圍與邊界

- **範圍**
  - 路由 `/library`（導向第一個媒體庫）、`/library/:libraryId`（`?page=`、`?filter=review|unmatched`）；
    取代 `/library/:routeSlug`，舊網址不留轉址（內部頁面，票面不要求）。
  - 兩種卡片：**Jellyfin 牆的卡片**（Jellyfin 的名稱與年份、疊上 Berth 狀態、深連結一定有）與**還沒進 Jellyfin
    的卡片**（TMDB 標題跟著 UI 語言、TMDB 海報、票 13 的 Jellyfin 那一行）。同一個元件，由資料決定樣子。
  - 媒體庫 id 不在允許清單、帳號停用、Jellyfin 連不上三種新狀態（§5）。
- **留位置給後面的票**（不做，但版面不為它們重排）：
  - **票 04**：Jellyfin 牆卡片的 2:3 海報位現在是一塊空的 `hull` 底，不印「沒有海報」——那句話在這裡是假的。
  - **票 05**：標識帶在名稱與盤點行之間插一行觀看狀態；「標為已看 / 未看」住在最下面那一行、深連結旁邊。
  - **票 06**：排序與類型、年份篩選加在篩選列那一排（窄版換行），狀態疊在同一個網址上（`sort`、`genres`、`years`）。
    換排序或篩選回到第 1 頁。**build 定案（2026-09-17，前三條使用者拍板）**：
    1. 「待審」「Unmatched」與排序、類型年份**並存於網址、各管各的**：切到待審時排序與類型年份留在網址上但不套用
       （Berth 的清單沒有 Jellyfin 的類型），控制項不畫；按「全部」回到原本排好、篩好的那一頁。
    2. 篩類型或年份時「還沒進 Jellyfin」那一條**收起**；只換排序時照舊。
    3. 控制項：排序鍵與方向各一個原生 `select`，類型與年份各一份勾選清單、勾了就套用、就地展開不開 dialog。
    4. 清單的開關是 `aria-expanded` 的按鈕、清單畫在整列控制項下方，**不是 `<details>`**（實跑：`<details>` 展開時
       旁邊的開關被擠到下一行、清單困在半欄寬）；一次開一份。方向另寫 `order`（只記 `Descending`）。
    5. 篩完一部都沒有：「這個媒體庫沒有符合篩選的作品。」+ 列出篩了什麼 + 「清除類型與年份」（排序留著）。
    6. 清單面板的狀態：讀取中「讀取中…」、失敗一句加「重試」、這個媒體庫沒有類型（年份）資料一句；有勾選時底下一顆
       「清除類型」「清除年份」。已選、但這個媒體庫沒有的值照樣列出來（jellyfin-web 同樣併起來），才取消得了。
  - **票 07**：切換列與「還沒進 Jellyfin」帶之間。
- **不做**：排序與篩選（06）、Jellyfin 的圖（04）、觀看狀態（05）、搜尋框、每頁筆數設定、Issue 篩選（M2）。
- **不碰**：探索頁、下載列表、Media 詳情、設計 token。
- **反目標**
  - 不做無限捲動或「載入更多」：網址記不住位置，鍵盤使用者到不了頁尾。
  - 不把 Berth 的作品混進 Jellyfin 的分頁結果：頁碼會與 Jellyfin 的總數對不上。
  - 不為沒有 Berth 經手的作品印任何狀態（「未追蹤」「不是 Berth 的」都不印）。
  - 不透出無權的媒體庫：不分辨「沒有這個媒體庫」與「你看不到它」。
  - 不用 `‹` `›` 之類的字元當分頁鍵的標記（會被念出來，DESIGN.md Don't）。
  - 不做 Jellyfin 式的整寬背景大圖與 hero。

## 5. 狀態與範圍值

### 頁面

| 狀態 | 樣子 |
| --- | --- |
| 讀取中 | 不動的空位格（`TilePlaceholder`），與探索牆相同 |
| Jellyfin 連不上（或拒絕 Berth 的 API key） | 取代切換列與牆：`blocked` 的 `Notice`「Berth 問不到 Jellyfin，媒體庫要靠它才知道你看得到哪些」+ 服務原文（`.value text-xs wrap-anywhere`）+ Ghost「重試」+ 連到健康頁。**build 定案**：允許清單的快取（60 秒）還在時切換列不問 Jellyfin、照樣畫得出來，只有牆換成這一塊——切換列說的是「你看得到哪些」，那個答案一分鐘內還算數 |
| 帳號在 Jellyfin 被停用 | 後端結束 session、回 401；前端重跑路由守衛，落到 `/login?expired`（「登入已失效」那一句） |
| 這位使用者沒有電影或劇集媒體庫 | 一句說明 + 下一步：`admin` 連到 Jellyfin 的媒體庫設定（主機推不出時只留文字），`user` 看到「請管理員在 Jellyfin 開放媒體庫給你」 |
| 網址上的媒體庫不存在或沒有權限 | **同一句**「找不到這個媒體庫，或你沒有權限看它」+ 連到第一個媒體庫 |
| 媒體庫是空的（Jellyfin 0 部、也沒有還沒進的） | 「這個媒體庫還沒有任何作品」+ 回探索頁。Jellyfin 0 部但上面那一條有作品時不說這句（code-review 抓到） |
| 頁碼超出範圍 | 「這一頁沒有作品」+ 回第 1 頁；分頁鍵照常 |
| 篩選後沒有 | 「這個媒體庫沒有待審的作品」/「…沒有 Unmatched 的作品」+ 回「全部」 |
| 後端不可達 | `inventory.off` 一句（沿用） |

### 卡片

**Jellyfin 牆的卡片**（在 Jellyfin 裡）：

| 行 | 內容 |
| --- | --- |
| 海報位 | 2:3 `hull` 空塊（票 04 填） |
| 第一行 | 類型代號 · 年份（Jellyfin 的 `ProductionYear`，沒有是 `—`）；Berth 經手時接狀態色塊與待確認色塊 |
| 名稱 | Jellyfin 的名稱，**不走 UI 語言**，沒有第二行原文 |
| 盤點行 | Berth 經手：`N / M 集入庫` 或 `N 個版本`（票 13）；否則這一行留白但保留高度 |
| 最下面 | 「在 Jellyfin 開啟」（主機推不出時「沒有 Jellyfin 位址」） |
| 連結 | 有 TMDB id（Jellyfin 的 `ProviderIds.Tmdb`，或 Berth 經手時 Berth 自己的那一個）→ 海報與標識帶連 `/media/:id`；沒有 → 那一塊不是連結，只剩最下面的深連結 |

**還沒進 Jellyfin 的卡片**：與票 13 相同——TMDB 海報、標題跟著 UI 語言（票 02）、狀態色塊、盤點行，
最下面是「Jellyfin 還在掃描」/「Jellyfin 找不到它」/ `—`，永遠沒有深連結。

**Berth 經手、在 Jellyfin 裡**的判定：Jellyfin 的作品與 Berth 的 Media 同型別（Series ↔ 劇集、Movie ↔ 電影）且
`ProviderIds.Tmdb` 相同，**或**帳本裡那部作品的 Series / Movie item id 就是它。只看帳本的話，
「反查找到了集、卻還沒有 Series id」的作品會掉進「還沒進 Jellyfin」（票 13 留下的缺口）。

狀態色塊、盤點行的定義與優先序沿用 `.scratch/m1/library-shape.md` §5，只是彙整範圍從一條 Route 換成
**指向這個媒體庫的每一條 Route**（一個媒體庫可以有兩條 Route，同一部作品不重複出現）。

## 6. 互動與版面

- **寬度**：`max-w-[110rem]`，與探索牆同寬；390px 時切換列、篩選列與分頁各自換行，不橫向捲動。
- **Tab 順序**：切換列 → 帶上的卡片 → 篩選列 → 上方分頁 → 牆 → 底部分頁。
- **分頁鍵**：Ghost 外觀的連結（它們換網址），文字就是「上一頁」「下一頁」；到頭的那一顆不是連結，
  `aria-disabled` 的 `ink-dim` 字，位置不變。`1–100 / 523` 走 `.value`。只有一頁時整組不畫，總數仍寫在篩選列旁。
  換頁之後牆上方那一行的 `aria-live` 念出「第 101–200 部，共 523 部」。
- **換媒體庫**時 `page` 與 `filter` 都不帶過去（那是上一個媒體庫的）。
- **篩選**不重抓：Berth 那一份清單跟著每一頁一起到手，篩選在前端做；數字由後端算、跟著牆那一支回來。
  篩選連結帶著現在的頁碼，換篩選不換頁，按回「全部」回到原本那一頁。篩選時帶子與分頁都不畫，
  牆上方的 `aria-live` 說「N 部」。
- **卡片**：兩條連結並排不巢狀（票 13）；框的 hover 用 `has-[a:hover]`。沒有 `/media` 連結的卡片，框只跟著
  深連結變重。
- **標題層級**：`h1` 媒體庫；帶子與牆各是 `section`，`aria-labelledby` 接各自的標題（牆的標題是 `sr-only` 的
  媒體庫名）；卡片名 `h3`。

## 7. 約束與不可自行發明的決定

- **權限**（plan §11.2b、研究 §9）：切換列只列 `UserViews` 裡的 `movies` / `tvshows`；網址上的媒體庫 id 由後端對
  允許清單驗，不在清單就 404 且不問 Jellyfin；前端不送、也拿不到任何 Jellyfin 使用者 id。
- **名稱**：Jellyfin 裡的作品顯示 Jellyfin 的名稱（使用者拍板，brief §7.5）；還沒進的跟 UI 語言（票 02）。
- **分頁**：每頁 100（jellyfin-web 的預設 `libraryPageSize`）、依 `SortName` 升冪（jellyfin-web 劇集庫與電影庫的
  預設排序；票 06 加選項：兩種媒體庫各自的選單，照 jellyfin-web）。頁數寫在網址（1 起算）；每頁筆數不讓前端指定。
- **判定規則在後端**：在不在 Jellyfin、連到哪一個 `/media/:id`、卡片狀態、兩個篩選旗標與數字。
- **The One Meaning Rule / The Usual Stays Unpainted Rule**：失敗 `blocked`、待審 `assigned`、下載中 `working`；
  已入庫、部分、空是中性；沒有 Berth 經手的作品沒有色塊。Jellyfin 連不上是 `blocked` 的 Notice。
- **i18n**：文案全走 key，zh-Hant 與 en 並列。作品名、媒體庫名、服務原文不是文案。
- **無障礙**：深淺兩主題文字 ≥ 4.5:1；390px 無頁面層級橫向捲動；外部連結說得出會開新分頁；分頁鍵 ≥ 24×24；
  換頁與篩選的結果進 `aria-live`。
- **不可發明**：`JobState` 的分組、深連結格式與主機推導（`services/deeplink.py`）、Specials 不進總數、反查 6 次的上限、
  哪些 collection type 瀏覽得了。
