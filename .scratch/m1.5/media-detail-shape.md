# Shape：Media 詳情 `/media/:id` 整頁重排——觀看區在上、Berth 的那一半在下（M1.5 票 08）

`/impeccable shape`，2026-09-18。視覺世界沿用 DESIGN.md「泊位調度板」，不新開世界。取代
`.scratch/m1/media-detail-shape.md` §3 的區塊序列（身分帶的內容、季表的判定、搜尋與結果表、檔案與版本的內部
沿用它與 `.scratch/m1/search-results-shape.md`、`.scratch/m1/library-shape.md`）。**本文件也是票 09（長清單收合）
與票 10（缺集一鍵搜）的版面契約**：它們往 §3 留的位置裡填，不重排。

使用者拍板三件事（2026-09-18，全數照推薦）：

1. **分層**：作品在 Jellyfin 裡、這位使用者看得到時，上面是**觀看區**（Jellyfin 的季與集：能看什麼），下面是
   **Berth 的那一半**（搜尋 → 季集與入庫 → 檔案與版本：缺什麼、拿什麼）。兩份季集各回答一件事，不合併
   （合併要以季集號對齊兩個來源，Jellyfin 認錯編號時整列對歪）。不在 Jellyfin 時少了觀看區，其餘順序相同。
2. **集是橫卡網格**：與首頁「繼續觀看」同一種 16:9 橫卡、同一份 `WALL_GRID`（Disney+、Plex 的季頁）。
3. **看到一半的項目按「標為已看」先就地確認**：它會把看到一半的位置歸零，找不回來（票 05 留下的待決）。
   媒體庫牆的切換鍵是同一個元件，一起改。

採用的慣例：季切換加同一頁列出那一季的集照串流 app（Netflix、Disney+、Apple TV）——jellyfin-web 是劇頁列季卡、
點進季頁才列集，Berth 的 `/media/:id` 是探索與媒體庫共用的一頁，不另開季頁；觀看標記、已看切換、`Resume`
主按鈕照 jellyfin-web（研究 library-browsing.md §7、§7.1）。

## 1. 工作與讀者

- **模式：Operate。** `admin` 與 `user` 都進得來。
- **兩個時刻共用一頁**：從媒體庫或首頁點進來的人多半是「**我要看這部**」——第一眼要是那顆「繼續看 S01E04」
  與這一季的集；從探索點進來、Jellyfin 裡還沒有的作品是「**這是不是我要的、要不要下載**」——第一眼要是搜尋。
  同一部作品入庫之後，這一頁從後者變成前者。
- **這一頁仍然是決策中心**（brief §13），只是決策多了一種：看哪一集。

## 2. 成果與證據

- **主要任務**：在 Jellyfin 裡——一按就落在 Jellyfin 的那一集（或那部電影）；挑別的季、別的集；標記已看。
  不在 Jellyfin——搜到 torrent、送單。
- **只有 Berth 說得出來的**：同一頁上同時看得到「Jellyfin 裡能看的」與「TMDB 上有、磁碟上缺的」。Jellyfin 只知道
  前者、索引站只知道後者。
- **權限是這一頁的真話之一**：這位使用者在 Jellyfin 看不到這部作品時，頁面上**沒有任何** Jellyfin 的東西——
  沒有觀看區、沒有 item id、沒有圖、沒有觀看狀態——版面就是「不在 Jellyfin」那一種，不說「你沒有權限」
  （分得出來就是在告訴人那部作品在哪裡，與媒體庫的 `LibraryNotVisibleError` 同一個道理）。
- **真實資料範圍**：
  - 劇集 1–35 季（含 Specials）；一季 1 到上千集（TMDB 把名偵探柯南併成一季 1213 集，Jellyfin 照 TMDB 就是一季）。
  - 集的劇照：Jellyfin 的集 `Primary`；很多集沒有（NFO 沒圖、掃描沒抓到），票 01 的 dummy 樹整季都沒有。
  - 季名是 Jellyfin 的，跟伺服器的 metadata 語言（`第 1 季`、`Season 1`、`Specials`、篇章名），不跟 UI 語言。
  - 集名是 Jellyfin 的；沒有集的 NFO 時是檔名（`Alpha Show`）。
  - 一部作品在 Jellyfin 可能有兩份（兩條 Route 分屬兩個媒體庫，plan §2.2），這位使用者可能只看得到其中一份。

## 3. 選定方向

- **視覺權威**：DESIGN.md。新東西都是既有的語彙：區塊標題（`.label` + 計數壓在重橫線上）、橫放的貨櫃（`WatchingRows`
  的橫卡）、導覽方塊（季切換）、主要按鈕（黃漆，整塊板唯一的主要動作色）、就地確認。
- **結構論點：提單上多了一欄「提貨」。** 身分帶仍是提單抬頭；在 Jellyfin 裡的作品，抬頭上蓋了一顆提貨章（主按鈕），
  底下第一疊是已經進倉、隨時可以提走的貨（觀看區），再下面才是還在碼頭外的（搜尋、季集與入庫、檔案）。
- **頁面序列**（同一份 DOM 順序，沒有 tab，不重排區塊內部）：

  | 順序 | 區塊 | 在 Jellyfin 裡 | 不在（或看不到） | 誰填 |
  | --- | --- | --- | --- | --- |
  | 1 | 身分帶：海報、標題、**一行識別值**、**主按鈕**、簡介、快照新鮮度 | 有主按鈕 | 沒有主按鈕 | 票 08 |
  | 2 | **觀看**：季切換 + 那一季的集（橫卡）；電影沒有這一區 | 有 | 不畫 | 票 08 |
  | 3 | **搜尋**：關鍵字、Route、搜尋鍵、會送出去的關鍵字、**入庫資料夾**、纜繩、結果表 | 有 | 有 | 票 08（10 往裡送查詢） |
  | 4 | **季集與入庫**（原本的「季集」，Berth 的季表）：工具列、各季 | 有 | 有 | 票 08 改名；09、10 填工具列與展開區 |
  | 5 | **檔案與版本** | 有 | 有 | 票 09 收合 |
  | 6 | TMDB 歸屬頁尾 | 有 | 有 | — |

- **身分帶改成一行識別值**：原本的剖面（`Cutaway` 五列 + 資料夾名說明）是 1280×900 下「搜尋」沉到 y=984 的主因。
  類型、首播 / 上映日、季集數（或片長）、TMDB id 收成標題下一行 `Dot` 分隔的 `.value text-xs`；**資料夾名搬進搜尋區塊**
  ——它是送單會寫死的那一串字，而送單在那裡（送單確認本來就再印一次）。主按鈕在識別值之後、簡介之前：簡介再長，
  主按鈕都在第一屏。窄版簡介佔整寬（不擠在海報旁那一條窄欄裡）。
- **焦點時刻**：主按鈕。整頁只有它是黃漆（搜尋鍵在它下面好幾屏；不在 Jellyfin 時搜尋鍵就是唯一那一顆）。
- **實作後果**：觀看區是另一支請求（`GET /api/media/{id}/watch`），**不擋頁面**：身分帶與 Berth 的那一半先畫，
  觀看區與主按鈕到了才插進來（首頁兩列的同一個取捨：讀取中不留空位，晚一點出現比先畫格子再消失好）。Jellyfin
  連不上、慢，搜尋照樣能用。

## 4. 範圍與邊界

- **範圍**
  - 後端：由 TMDB id 找這位使用者看得到的作品、確認可見性、季、這部作品的下一集、某一季的集（§7 的閘門）；
    `GET /api/media/{media_id}/watch`、`GET /api/jellyfin/shows/{series_id}/episodes?season_id=`。
  - 前端：身分帶改版、觀看區、主按鈕、`WatchToggle` 抽成共用元件、搜尋纜繩收合、資料夾名搬家、季表改名。
  - 媒體庫牆的切換鍵跟著改確認規則（使用者拍板第 3 件）。
- **留位置給後面的票**（不做，但版面不為它們重排）：
  - **票 09**：「季集與入庫」標題列下方一條**工具列**（`只看缺集`、之後的收合控制都放這裡；沒有控制項時不畫、不留高度）；
    季列的集表只在展開時渲染、展開的一季在自己的頂端與底端都收得起來——這些都在第 4 塊裡。「檔案與版本」的收合在第 5 塊裡。
  - **票 10**：缺集一鍵搜的入口住在**第 4 塊**：整部作品的入口在工具列，單季的入口在那一季**展開區的第一行**
    （不在 `<summary>` 裡，The Summary Is One Button Rule）。按下去**不在第 4 塊裡另開結果表**：它把查詢交給第 3 塊那一個
    搜尋區塊（關鍵字預覽換成後端給的那幾個），焦點移到第 3 塊的標題，結果照舊畫在那裡、照舊送單。
- **不做**：劇集整部或整季的「標為已看」（媒體庫牆有整部的；整季沒有人要）、集的簡介與片長（橫卡放不下，要看就開 Jellyfin）、
  在 Berth 裡播放、「從頭播放 / 繼續播放」二選一（Jellyfin 那一頁自己有）、季切換寫進網址。
- **不碰**：搜尋結果表與送單、季表的判定與欄序、檔案與版本的內容、探索頁、首頁兩列、設計 token。
- **反目標**
  - 不做 tab 把觀看與取得分開（M1 shape §4：它們是一條順序，不是兩個頁面）。
  - 不做 Jellyfin 式的整寬背景大圖（The Paint Needs A Painted Ground Rule）。
  - 不在劇照上疊進度條、勾勾或色塊；已看、看到幾 % 是標識帶上的一行字（The Usual Stays Unpainted Rule）。
  - 不橫向捲動集的清單（The Board Never Scrolls Rule）。
  - 不透出看不到的作品（§2），也不把 Jellyfin 的 item id 放進 `/api/media/{id}` 那一份回應。

## 5. 狀態與範圍值

### 身分帶的主按鈕

| 狀態 | 按鈕 | 下面一行 |
| --- | --- | --- |
| 劇集，下一集看到一半 | 「繼續看 S01E04」 | 集名 `Dot` 看到 18% |
| 劇集，下一集沒開始（看過前面的） | 「看下一集 S01E05」 | 集名 |
| 劇集，一集都沒看過 | 「從 S01E01 開始看」 | 集名 |
| 劇集，全部看完 | 「在 Jellyfin 開啟」（連到劇） | 全部看完了 |
| 電影，看到一半 | 「繼續看」 | 看到 42% |
| 電影，沒看或看過 | 「在 Jellyfin 看」 | 已看（看過時） |
| 主機推不出 | 不是連結，換成一句「不知道 Jellyfin 開在哪裡」（`inventory.jellyfin.noAddress`） | — |
| 不在 Jellyfin、看不到、還在讀、讀取失敗 | 不畫 | — |

主按鈕一律開新分頁（`sr-only` 說明），`aria-describedby` 指到下面那一行。**是連結不是按鈕**：它換頁。
電影的「標為已看 / 未看」在主按鈕旁邊（電影沒有觀看區）。「下一集」是哪一集由 Jellyfin 算（`/Shows/NextUp?seriesId=`），
Berth 不自己推。

### 觀看區

| 狀態 | 樣子 |
| --- | --- |
| 讀取中 | 不畫（區塊與主按鈕都不畫、不留空位） |
| 不在 Jellyfin、或這位使用者看不到 | 不畫；後端回 `null`，回應裡沒有任何 Jellyfin 的欄位 |
| Jellyfin 連不上 | 第 2 塊的位置換成一行 `ink-dim`「問不到 Jellyfin，觀看區暫時看不到」+ 服務原文 + Ghost「重試」（首頁那一列的形狀），版面照「不在 Jellyfin」排 |
| 帳號在 Jellyfin 被停用 | 後端結束 session、回 401；`SessionEnded` 送回登入頁（首頁同一條路） |
| 劇集沒有任何季（剛掃到、還沒分季） | 標題列照畫，一句「Jellyfin 還沒有這部作品的集」 |
| 標題列 | `觀看` + 計數位置說「剩 N 集沒看」/「全部看完了」+ 右邊「在 Jellyfin 開啟」（劇） |
| 季切換 | **兩季以上才畫**（build 定案，§9）；一排導覽方塊（`NAV_BOX`，選中是重線 + `deck` 底），`aria-pressed`；文字是 Jellyfin 的季名；預設選下一集所在的那一季，沒有下一集時選第一個季號 ≥ 1 的季，再沒有就第一季；35 季就換行，不捲動 |
| 那一季讀取中 | 不動的 `deck` 空位格（6 格，一行），切季時先留著上一季的集（`placeholderData`，焦點留在季切換上） |
| 那一季讀取失敗 | 一句 + Ghost「重試」；季切換照常 |
| 那一季沒有集 | 一句「這一季在 Jellyfin 還沒有集」 |
| 一季上千集 | 整季照畫、圖 `loading="lazy"`；只會畫選中的那一季（原本的季表一次畫全部）。真的慢再量（票 09 的量法） |

### 集的橫卡（`WatchingRows` 的橫卡加一條切換行）

| 行 | 內容 |
| --- | --- |
| 圖 | 16:9，**集自己的 `Primary`**（劇照）；沒有就印「無圖」——不借劇的橫圖，整季一模一樣的圖沒辦法用來挑集 |
| 第一行 | `S01E04`（`episodes.ts`；多集檔 `S01E04-E05`、Jellyfin 認不出編號時只剩有的那一段）；是下一集時後面接中性小色塊「下一集」或「繼續看」 |

| 觀看 | 「已看」「看到 42%」（`services/watch.py` 的判定），沒看過留空但保留高度 |
| 最下面 | `border-t-2 border-rule` 一行：「標為已看 / 未看」（小一號按鈕），確認就地展開佔滿這一行、兩顆鍵疊一欄 |
| 連結 | 上面那一塊（圖到觀看那一行）是一條連結，開 Jellyfin 那一集的詳細頁、新分頁；最下面那一行不在連結裡（並排不巢狀） |

### 已看切換（共用 `WatchToggle`：觀看區的集、電影、媒體庫牆）

| 動作 | 確認 |
| --- | --- |
| 標為未看 | 就地確認（沿用票 05：清掉觀看次數與時間，劇集清的是每一集） |
| 標為已看，看到一半（`progress` 有值：集、電影） | **就地確認**：「會清掉你看到 42% 的位置，清掉就找不回來。」 |
| 標為已看，劇集（媒體庫牆） | **就地確認**：「每一集都會標為已看，看到一半的集位置歸零。」——劇集的觀看紀錄看不出底下有沒有看到一半的集，所以一律說 |
| 標為已看，沒有進度的集或電影 | 一按就送 |

寫入之後：集的卡片拿回應就地改那一格（不重抓那一季）；主按鈕與「剩 N 集沒看」重問一次（下一集可能換了，它們在
上面、位置不動）。媒體庫牆照票 05 就地改那一格。

### 搜尋區塊（票 08 改兩處；票 10 加第三處）

- **資料夾名**：搜尋列下方、關鍵字預覽之後一列 `dl`：term `.label`（「入庫資料夾（將會是）」/「入庫資料夾」）+ `dd` `.value
  wrap-anywhere`，底下一行 `text-xs text-ink-dim` 說它什麼時候定下來（原本身分帶上那兩句）。
- **纜繩收合**：搜尋中照舊逐條亮（署名互動）；結束之後**成功的纜繩收成一行** `<details>`：「問了 N 個關鍵字，全部有回應」
  （部分失敗時「N 個有回應」），展開才逐條列；**失敗的那幾條不收**，照舊一條一條畫在摘要上面、原文就地展開
  （The Needs-You Floats Up Rule）。
- **缺集模式說得出範圍，也回得去**（票 10 加，2026-09-19）：從季表按進來時，關鍵字預覽那一行的引言換成
  「這部作品缺的那幾集，Berth 會這樣問：」/「S01 缺的那幾集，……」，旁邊一顆小一號的「改回作品名搜尋」。
  §4 原本只寫「關鍵字預覽換成後端給的那幾個」，沒有說怎麼回去——沒有出口的話，按進來之後只剩重整一招。
  關鍵字欄位仍然壓過一切：自己打字就只問那一個（票 08 的規矩不變），所以按下缺集入口時關鍵字會被清空。

## 6. 互動與版面

- **寬度**：`max-w-[80rem]`（決策與清單頁），外緣 `px-6 py-8`。
- **身分帶**：`sm` 以上 `grid-cols-[11rem_minmax(0,1fr)]`，海報在左、右欄依序：已追蹤色塊 → `h1` → 英文 / 原文標題 → 識別值那一行
  → 主按鈕（`sm:max-w-xs`）與它下面一行 → 簡介 → 快照新鮮度。窄版海報 7rem 與標題並排，**主按鈕、簡介、新鮮度改成整寬**
  （在海報那一列下面）。
- **Tab 順序**：略過海報 → 主按鈕 →（電影）切換鍵 → 重新抓取 → 觀看區「在 Jellyfin 開啟」→ 季切換 → 每一張集卡（連結 → 切換鍵）
  → 搜尋 → 季集與入庫 → 檔案 → 頁尾。
- **標題層級**：`h1` 作品名；觀看、搜尋、季集與入庫、檔案與版本各是 `section` + `h2`；集卡的集名不是標題（整塊是連結，
  連結名就是季集代號 + 集名 + 觀看狀態）。
- **回饋**：切換結果就地換字（`aria-live` 由按鈕文字本身承擔，同媒體庫牆）；切季不宣告（`aria-pressed` 已經說了）。

## 7. 約束與不可自行發明的決定

- **權限**（plan §11.2b、研究 §2、§9、§10），全部集中在 `services/jellyfin_access.py`：
  1. **找作品**：`GET /Items?userId=&recursive=true&includeItemTypes=<Series|Movie>&hasTmdbId=true&fields=ProviderIds`，
     **不帶 `parentId`**（Jellyfin 才照這個人的 `UserViews` 限縮），Berth 端比 `ProviderIds.Tmdb`，或帳本記下的 Series / Movie
     id（媒體庫牆的同一條規則：Jellyfin 認錯 TMDB id 時帳本那一個才是對的）。兩份都看得到時先取帳本那一份。
  2. **確認可見性**：`GET /Items/{id}?userId=`（看不到回 404）。**這部作品的 NextUp（`seriesId`）只在這一步 200 之後才問**
