# 追更 shape（M5.5 票 12）

2026-11-04。使用者確認兩件事：**「晚 N 天」從播出日算**（10/28 播出、10/31 那天寫「晚 3 天」，與門檻設多少無關）；
版面是**桌機表格、窄版疊成列**。其餘照 `DESIGN.md` 的既有方塊（區塊分頁、`SectionHeading`、`CollapsibleRow`、`Notice`）。

## 誰、在什麼時候

- 管理員（Operate 模式）。收到「有 N 件等你處理」，或沒接 Discord、想知道「我追的有沒有按時進來」時打開。
- 成功：一眼看出哪幾部晚了、晚幾天、卡在哪一步，點進作品頁或那一筆下載處理；準時的不用看。
- 量級：訂閱的作品一季 5–30 部；「要你動手」平常 0–3 部；「斷更很久」累積幾部到十幾部。

## 對象與欄位

- **哪幾部**：與遲到提醒同一份對象（`sweep._watched_series`：現在還訂著、帶著 Item 的綁好的 RSS Series 的作品）。頁面與 Issue 說的是同一群作品。
- **作品**：顯示用標題（Display Round），連 `/media/:id`。
- **字幕組**：作品上每一條 Series 的字幕組名（Mikan 的 subgroup，沒有就從發佈名讀），多條以 `、` / `, ` 接。
- **已播到**：TMDB 上最新播出的一集（第 0 季不看）`S02E05` 加播出日；沒播過寫「還沒播」。
- **已入庫到**：帳本裡最新的一集 `S02E04`；一集都沒有寫「還沒有」。
- **狀態**：
  - 看的是**基準之後**（最後入庫那一集之後；沒入庫過從最早那條 Series 建立之後）已播、還沒入庫的集，與遲到判定同一段。每一集照 `domain.conclude`，整部取 `overall`；這段沒有集時是「跟上了」。
  - **下載停滯**：結論是 `downloading`，但蓋到那幾集的 Job 在路上的只有 `stalled`（沒有還在動的、也沒有下一輪就送的 Item）——`WhyNot` 把它併進下載中，這一頁拆出來。
  - **晚 N 天**：遲到判定（`parser.overdue`，含門檻、兩種例外）算出晚的集時才有；N 是最早那一集晚的集**從播出日到今天**的天數（容器時區）。後面寫晚的集（`S02 E05–E06`）。
  - **可能是下一輪**：判定的理由是 `next_run` 時接在「晚 N 天」後面。
  - 卡在 `stalled` / `import_failed` / 送單失敗 / 沒下載成的那幾筆 Job 連 `/jobs/{hash}`（判定的 `LateEpisode.jobs`，最多一筆，「看這筆下載」）。

## 分段與排序

```
桌機（≥ lg）
[時間表] [追更] [訂閱 1]
追更
（收不到通知時）┌ 遲到只會顯示在這裡，不會通知你。到通知設定 ┐
要你動手 2 ─────────────────────────────────────────────
作品          字幕組      已播到         已入庫到   狀態
藥師少女的…   LoliHouse  S02E05 11/01   S02E04    [晚 3 天] S02 E05 · 下載停滯 · 看這筆下載
Re:Zero      ANi        S03E09 10/29   S03E08    [晚 6 天] S03 E09 · 可能是下一輪 · 沒有來源
準時 14 ────────────────────────────────────────────────
…
▸ 斷更很久 3                                       展開
```

- **三段**，各一個 `SectionHeading`（標題 + 部數）：
  1. **要你動手**：有晚的集，或結論是入庫失敗、沒下載成、等審核、待綁定、下載停滯（還沒過門檻也算：它不會自己好）。照 N 由大到小，沒有 N 的排後。
  2. **準時**：其餘。照「已播到」的播出日新的在前。
  3. **斷更很久**：判定因 60 天視窗不再提醒的（基準之後有缺、最後一集缺集播出滿 60 天）。`CollapsibleRow` 同款的原生 `<details>`，**預設收起**，摘要列寫部數。
- 某一段沒有作品時整段不畫；「要你動手」沒有時第一行寫「訂閱的作品都按時」（`ink-dim`），不畫空段。

## 版面

- **桌機（`lg` 以上）**：一張 `<table>`（`caption` 是段名，`sr-only`；`th scope="col"` 欄頭 `.label`），一段一張、欄寬一致（`table-fixed`）。列之間 `border-b-2 border-rule`。季集與日期 `.value tabular-nums`。頁寬 `max-w-[80rem]`（決策與清單）。
- **窄版**：同一份資料，每部作品一塊 `well` 底 + `border-2 border-rule`：第一行作品名，第二行狀態，下面三條 `.label` 欄名 + `.value` 值（字幕組、已播到、已入庫到）。不是另一份元件邏輯，只是換排法（`<table>` 在窄版用 `display:block` 疊列，或同一份資料畫兩次、各自 `hidden`；後者較穩，選它）。
- **漆**：只有「晚 N 天」塗 `assigned`（現在需要你）。其餘狀態只是字（The Usual Stays Unpainted Rule）：一頁都準時時畫面上沒有任何信號色。「可能是下一輪」、「下載停滯」是字。
- **頁首提示**（收不到通知時）：中性 `Notice`（不是 `blocked`：不擋任何事），一句話加連到 `/settings/notifications` 的 `INLINE_LINK`。條件讀 `GET /me/notifications`：沒有 bot、沒填 Discord ID、沒勾「等你處理」（`waiting`）、或 Discord 上次說到不了（`unreachable_at`）。四種一句話說，不分開說原因（原因在通知設定頁）。讀不到這一份時不畫（不猜）。

## 分頁列

- `AiringTabs`：時間表（每個人）、**追更**（admin）、訂閱（admin）。
- 區塊設定收成一份（票 07 / 09 留下的）：一個區塊物件帶 `to`、`pages`、分頁（`to`、標籤、只給 admin 嗎、件數怎麼算），頁首的 `SectionLink` 與 `SectionTabs` 都讀它。加一頁只改那一份。

## 時間表卡片的「晚 N 天」

- 卡片上那一集是那部作品遲到判定裡晚的集時，狀態是「晚 N 天」（N 同上，從那一集的播出日算）；蓋過已訂閱。已入庫仍最優先。
- 每個人都看得到這個類別（同已訂閱、已入庫），字幕組與 Feed 照舊不送。**時間表上是中性色塊**：那一頁的狀態是事實，一般使用者也看得到，他動不了手，`assigned` 對他不成立。

## 狀態

- 讀取中：三段的位置先畫一段、幾列等高空位（不跳版）。
- 讀不到：`RequestFailed`。
- 一部訂閱都沒有：一句話加連到時間表（找新番）的連結。
- 作品沒有 TMDB 快照：已播到寫「還沒抓過 TMDB」，狀態空著，排在準時段最後。

## 不做的

- 排序切換、篩選、逐集展開（逐集在作品頁）。
- 頁上直接忽略或處理 Issue（在 `/issues`）。
- 其他通知管道（ADR-0015）。
