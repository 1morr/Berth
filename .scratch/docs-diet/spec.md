## 共同規則（每張票都守）

1. **封存**：M0–M5 的東西搬到 `docs/archive/<里程碑>.md`，檔名同 `.scratch/` 目錄名（`m0`、`m1`、`m1.5`、`m2`、`m3`、`m4`、`m5`）。引用跟著改。
2. **搬移要證明沒丟**：`scripts/docs_moved_lines.py`（票 01 寫）比對「開工 commit 之後從來源檔刪掉的每一行，都出現在目的檔」，輸出貼進票的 `## Comments`。
3. **改寫要證明沒丟決定**（04、05 系列）：Comments 放對照表「舊版的每個決定 / 規則 → 新版位置或 ADR」；收尾 code-review 的 Spec 軸逐節對照 `git show <開工 commit>:<檔>`。
4. **章節編號不變**：`berth/`、`web/` 引用 plan §11.x 84 處、brief §20.x 298 處、plan §3.2 141 處，這輪不能改它們。標題文字可改；號碼不改、不重排；整節搬走的留標題加一行指向 archive。
5. **範圍**：只動 `docs/`、`tests/`、`scripts/`、`CLAUDE.md`、`CHANGELOG.md`、`.scratch/docs-diet/`；不改 `berth/`、`web/`。唯一例外（使用者 2026-10-30 同意）：`berth/models/__init__.py` 與 `berth/migrations/versions/8b1e1dc5336b_m0_tables.py` 的 docstring 指向「progress.md 偏差與決定」，票 01 改成指 archive，只改那一行說明文字。
6. **歷史快照不改**：`docs/research/`、`.scratch/` 已完成的票、`docs/archive/` 搬進去的原文。
7. **矛盾不自己挑**：改寫時發現 plan 與 brief 互相矛盾、或分不出哪個是現況，列在票 Comments 問使用者。
8. 一個 session 一張票；本機 commit 不用問；push 先問。

## 改寫規則（04b、04c、05a–05e）

- **只寫現況**：刪「原寫」「取代原」「某日改」「推翻」「之前是」與標題上的【決定，日期 改】（留【決定】）。舊說法靠 git 與 archive 找得到。
- **票號與日期**：只在它是唯一的證據指標時保留，並改成連結（ADR、`docs/research/`、測試檔）；其餘刪。
- **為什麼**：理由是現況的一部分（不知道就會改錯的）才留，一兩句；更長的連到 ADR。
- **一段一件事**：長段落拆成清單或表；不為縮短而改寫意思。
- **開工先量**：本票範圍的大小與歷史標記數（`grep -cE '取代原|原寫|推翻|20[0-9]{2}-[0-9]{2}-[0-9]{2}|票 ?[0-9]+|[0-9]{2}-[0-9]{2} 改'`），收尾再量一次，前後貼 Comments；剩下的標記逐條說明為什麼留。
- **對照表**：Comments 裡逐節列「舊版的每個決定 / 規則 / 數值 → 新版位置」，code-review Spec 軸照它對 `git show <開工 commit>:<檔>`。
