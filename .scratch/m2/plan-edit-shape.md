# `/review` 的 `plan` 那一類（M2 票 07，`/impeccable shape`）

2026-09-23。視覺世界沿用 DESIGN.md 的「泊位調度板」；模式 **Operate**。前例是
`.scratch/m2/review-shape.md`（票 06 的佇列骨架與 `QueueRow`），這一份只寫它沒回答的。

## 工作與使用者

**誰來**：admin，被一筆停在「待審核」的下載叫來——常常在手機上。**他要做的一件事**：讓這一包
入庫，而且落在對的集上。典型是一包 12–39 個檔案裡**一到五列**說不清楚（絕對編號有反證、兩個檔案
撞同一集、Route 不讓 medium 自己進），其餘早就算好了。

**成功的樣子**：看得到那幾列會落在哪一條路徑、改得動、按一次核准，那一列從佇列上消失，下載開始入庫。

**這裡獨有的真話**：Plan 在核准前**不碰任何檔案**（PRODUCT 原則 2），所以改錯的代價是零——
代價只在按下核准那一刻。畫面要讓「核准之後會發生什麼」在按之前就看得到：每一列的目標路徑。

## 使用者拍板（2026-09-23，四題全照建議）

1. **核准＝照提案入庫**。待審核的列只要季集完整，就照畫面上的提案與目標路徑入庫；沒有提案的列
   （光碟、推不出季集）與兩列寫到同一條路徑，會**擋住核准**並說出是哪幾列。
2. **表格在佇列那一列裡就地展開**，不換頁（手機上審核要做得完，plan §7）。
3. **逐列「改」→「套用」**：那一列就地變成小表單，套用立刻存（`PUT /plans/{id}/items`），
   回應帶回新的目標路徑、當場顯示；不合法的改動就地說原因。核准是另一顆。
4. 舊格式的英文理由由 migration 清空（重新規劃就重算）。

## 一列的形狀（套 `QueueRow`）

- **標籤**：「待審核」/「Needs review」（中性色塊）。**標題**：作品名（跟 UI 語言）；沒有作品時退回發佈名。
- **一句話**：`review_reason` 翻成的下一步（`low_confidence` → 「有幾個檔案的季集要你確認」之類），
  接「等候於 …」。
- **展開（`<details>`）**：所屬下載（發佈名，連 `/jobs`）、計數（要入庫 N 個、高 / 中 / 低）。
- **計劃本體（不收在 `<details>` 裡）**：這一類的工作就是這張表，收起來等於多一次點擊。
  - **要人看的列攤在最前**：待審核、對不到、逐列改過的、有錯誤的。一列三行：
    1. 季集（`S01E05`、多集 `S01E05–E06`，沒有是「—」）＋ 來源檔名（`.value`，換行不截斷）。
    2. **→ 目標路徑**，或為什麼沒有：「核准後不會寫進媒體庫」（略過 / 對不到）、
       「還沒有季集，先改這一列」（沒有提案）。
    3. 信心 ＋ 理由（翻譯過的句子，`ink-dim` 小字，逐條一行）。
    - 右側（窄版在下方）一顆 ghost「改」。
  - **其餘的列**照 `/jobs` 現有的分組收著（處置 × 季 × 信心，一組一行），展開後同樣逐列可改。
- **改的表單**（就地取代那一列的第 1–2 行）：動作 `<select>`（選項由後端給，依檔案分類）、季、
  起集、迄集。動作不是「入庫」或作品是電影時季集欄不出現。「套用」（ghost 實線）與「取消」；
  取消與套用成功都把焦點送回那一列的「改」。失敗就地 `Notice signal="blocked"`：理由句子＋原文。
- **動作列**（照後端 `actions`）：
  - **核准並入庫**：主要動作（`assigned` 黃，它是這一列唯一「需要你」的那一顆）。不另外確認——
    目標路徑已經在畫面上，確認一次等於問第二遍（原則 2 的「先給看」已經做到了）。
  - **拒絕**：就地確認，後果照實說——「丟掉這份計劃（包括逐列改過的），Berth 重新規劃一次。
    檔案不動。」（plan §3.1：`review → completed`，規劃器下一輪整份重算。）

## 狀態

| 狀態 | 畫面 |
| --- | --- |
| 讀取計劃中 | 那一列的表格位置一塊靜態佔位 |
| 套用中 / 核准中 | 該按鈕「處理中…」並 `disabled` |
| 套用被拒 | 那一列就地 Notice（`episode_range_reversed`、`action_not_allowed`、`target_clash`…） |
| 核准被拒 | 動作列上方 Notice，說出擋住的是哪幾列（`undecided` / `target_clash`）＋ 原文 |
| 另一個分頁先處理了 | 409 的句子，重問佇列，那一列自己消失 |
| 核准成功 | 那一列消失；`aria-live`「已核准，開始入庫」 |

## 範圍與約束

- **不做**：多份 Plan 一起勾選核准（「批次」指的是一份 Plan 一次核准）、改作品（換 Media 是 rematch
  與重新入庫的事）、改 Tags、改已經入庫過的列（票 08 的 rematch）。
- 目標路徑**後端算**（`naming/` 純函式），前端不重算；動作選項也由後端給。
- 全部文案走 i18n，zh-Hant / en 並列；理由 code 以產出的型別為鍵，少一句是 `tsc` 錯誤。
- WCAG 2.2 AA：純鍵盤走得完（改 → 欄位 → 套用 → 核准），欄位有可見 `<label>`，錯誤以
  `aria-describedby` 關聯，結果 `aria-live`。
- 窄版 390px：表單欄位兩欄格線（季｜動作、起集｜迄集），路徑 `wrap-anywhere`，無橫向捲動。
- `/jobs` 展開區的 `JobPlan` 保持唯讀，但理由改走同一個翻譯函式；它那幾句「M1 還沒有審核佇列」過時了，
  改成指向 `/review`。
