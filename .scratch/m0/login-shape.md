# Shape：登入頁 `/login`（票 07）

`/impeccable shape 登入頁`，2026-09-08。視覺世界沿用票 05 鎖定的「泊位調度板」
（`.impeccable/surfaces/web-src-pages-setuppage-tsx.md`），本頁不另開世界。

## 1. 工作與對象

**Visitor mode: Operate。** 兩種人會看到這一頁：

- 剛跑完精靈的自架者 —— 他三分鐘前才在精靈裡打過同一組帳密（那組帳密被拿去建了 Jellyfin 管理員）。
- 被主人加進 Jellyfin 的家人 —— 他從來沒看過精靈，只知道自己有一個 Jellyfin 帳號。

桌機為主，手機要真的能用。**這一頁的正常狀態是看不到它**：session 30 天，多數人一個月才遇到一次。
看得到它通常代表：剛設定完、換了瀏覽器、session 過期，或被踢出來了。

## 2. 成果與證據

打兩格、按一顆按鈕、落到首頁。

畫面上唯一的「證據」是一句產品真相：**Berth 沒有自己的密碼**（brief §11）。它一次解釋三件事——
為什麼要打 Jellyfin 的帳密、為什麼這裡沒有註冊也沒有忘記密碼、以及為什麼 Jellyfin 掛掉時誰都進不來。
**不顯示 Jellyfin 的位址與版本**（使用者決定）：這一頁匿名可達，內部主機名不該送給沒登入的人。

## 3. 選定的方向

**單一登船口窗格**，不畫泊位板。泊位板講的是精靈那四個泊位，登入時一個都還沒開始——把它搬過來只是
把同一組色塊當壁紙用。

- 頁首只有一條重橫線：`BERTH` 字標 + `ZH / EN`。沒有 tagline，沒有導覽。
- 窗格居中，最大寬度約 26rem，垂直置中偏上。標題列是 `BTH 0` 塗裝色塊（中性色，不是信號色）+ 「登船口」。
- 欄位、按鈕、錯誤塊全部沿用 `components/controls.tsx` 的 `Field` / `PasswordField` / `PrimaryButton` /
  `Notice`。這一頁不引入任何新元件，也不需要 Radix。
- 窗格下方一行小字承載那句產品真相。

**署名互動不在這一頁。** 靠泊序列是精靈的簽名，登入只是一道閘門；它的品質表現在「錯誤說得出下一步」，
不在動效。

## 4. 範圍與界線

- 只做 `/login` 這一頁、`AppShell` 的身分區、以及路由守衛。設定頁、使用者管理、個人偏好都不在票 07。
- **不做**：記住我（session 本來就 30 天）、忘記密碼（密碼歸 Jellyfin 管，Berth 改不了）、註冊、
  Jellyfin Quick Connect、OAuth、頭像。
- 精靈頁與健康頁的既有視覺不動。

## 5. 狀態與範圍值

| 狀態 | 畫面 |
| --- | --- |
| 靜止 | 兩個欄位皆空；主要動作可按（送出後才驗，空白由後端一併拒絕） |
| 送出中 | 按鈕變「登入中…」，兩個欄位與按鈕 disabled |
| 憑證被拒（401） | `blocked` 色塊：「帳號或密碼不對」。**不分辨是哪一個**。帳號保留、密碼保留，焦點回到密碼欄 |
| Jellyfin 連不上（503） | `blocked` 色塊，另一句話：「連不上 Jellyfin。Berth 的帳號來自它，它沒起來就沒有人登得進來。」附一條可複製的 `docker compose ps jellyfin` |
| 被導來（session 過期） | `assigned` 色塊：「工作階段已過期，請重新登入。」 |
| 精靈還沒跑完 | 這一頁不該存在 → 導向 `/setup` |
| 已經登入 | 導向原本要去的地方，沒有就回 `/` |

帳號長度 1–255 字元，可能含 CJK；密碼可能是空字串（Jellyfin 允許無密碼帳號，Berth 一律拒絕並回同一句
「帳號或密碼不對」）。

## 6. 互動與版面

- 原生 `<form>`：Enter 直接送出。密碼欄沿用既有的「顯示 / 隱藏」。
- `autoComplete="username"` 與 `"current-password"`，密碼管理器才填得進來。
- 錯誤塊 `role="alert"`，非同步結果讀得到；`aria-busy` 標在送出中的表單上。
- 純鍵盤走得完，焦點永遠可見（既有的雙環 focus ring）。
- 窄版：窗格撐滿寬度減 padding。**不用 sticky 底部動作**——這一頁只有兩個欄位，永遠不會長到要捲。

**登入後的頁首**（`AppShell`）：`BERTH` + tagline 在左；右側依序是角色色塊、名字、「設定」、「登出」、
`ZH / EN`。角色色塊用**中性色**（`bg-deck`）：角色不是狀態，四個信號色各自只有一個意思，不能拿來當標籤。
`admin` 才看得到「設定」（連到 `/setup`）；`user` 看得到自己的角色，所以他知道自己為什麼沒有那顆按鈕，
而不是以為壞了。

## 7. 限制與不可自行決定的事

- React 19 + TS + Tailwind v4 + TanStack Router / Query + react-i18next；文案全走 i18n key，zh-Hant 與 en 並列。
- WCAG 2.2 AA 是驗收條件，深淺兩主題都要達標。
- session cookie 是 httpOnly，前端**讀不到它**：登入狀態只能靠 `GET /api/auth/me`，不能靠 JS 讀 cookie。
- 401 的處理只有一種：導向 `/login`。不做自動重試，不做 refresh token。
- 「非 admin 看不到設定入口」在前端是隱藏 + 路由守衛，在後端是 403。兩邊都要，前端那份不是安全機制。
