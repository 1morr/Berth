# 決策紀錄

專案做過的決定，一條一行，只追加。現在的做法寫在 brief、plan、ADR 與 spec；這裡記的是「誰在什麼時候定了什麼」，並連到寫著細節的地方。

## 寫法

- 一條一行：`- <日期> <里程碑>（<決定者>）：<決定，一句>。<細節在哪：ADR、票、brief 的章節>`，整行不超過 200 字元。
- 決定者三選一：`（使用者定）` 使用者自己定的、`（使用者同意）` agent 提議而使用者同意的、`（Agent 定）` 使用者沒看過的。
- 要記的：訪談與規劃時定下的、推翻先前決定的、做票時在兩種做法之間選的。照票面與文件做、沒有選擇的不記。
- 做票的分支不改本檔：票的 Comments 留 `決定：<一句>（<決定者>）` 行，合併的人在主分支抄成這裡的一條（`CLAUDE.md`〈每個 session 的流程〉）。其他 session（訪談、規劃、開工、驗收票）自己加。
- 需要寫理由、難回頭的架構決定另寫 ADR，在這裡佔一行並連過去。
- 推翻舊的一條時加新的一條，寫明推翻哪一條的日期；舊的那條留著。
- 找某個里程碑的決定用 `grep`，本檔不必整份讀。
- `tests/unit/test_progress_rules.py` 守〈紀錄〉每條的長度、里程碑標記與決定者（2026-11-12 起的）。
- M0–M5.6 的決定跟著里程碑封存在 `docs/archive/<里程碑>.md` 的〈偏差與決定〉，沒有搬過來（上千條、合計數十萬字）；總覽頁（`/1morr:dashboard`）會一起讀。
