# RSS 以 RSS Series 為單位：全部接受只排除、綁定時補齊舊集、Feed 必選 Route

取代原本的 Rule（先綁一部作品、再挑字幕組白名單與優先序）。決定：

- **RSS Series 由 Feed Item 自動長出**（Mikan 用番組 id + 字幕組 id，其他來源用標題骨幹 + 字幕組）。**全部接受、只排除**（三層關鍵字或正則，預設只排合集），不做字幕組白名單與優先序；同一集兩個字幕組都要（使用者實際訂閱就是這樣）。有把握自動綁定 TMDB，沒把握進待綁定。
- **Series 保留、以作品呈現**：使用者試跑時問過有沒有必要（當季播完就永遠留著、畫面上是 Mikan 的數字 id），結論是保留，改的是呈現。它是「番組 × 字幕組 → 作品、Route、季號與 offset、第一批」的記憶，拿掉就得每一筆 Item 重認作品、修正沒地方存（AutoBangumi 同樣每個番組 × 字幕組一筆）。RSS 頁以作品分組、完結的自動收進「已完結」（紀錄不刪）。
- **綁定時一律補齊舊集，不加開關**（使用者 2026-09-26 在討論過「只下載 feed 裡有的」與 Feed 層開關後維持）。一次送出上百個 torrent 的後果由在途量磁碟門檻與暫時失敗的有限重試承接。
- **Feed 帶劇集、電影各一條 Route，那一種有啟用中的 Route 就必填**（2026-10-16 推翻「不指定」）：Sonarr 的 Import List 本來就把 Root Folder 列為必填，「不指定」只多一次摩擦——同類型兩條以上 Route 收得下時停在待綁定，使用者再選一次，結果與自動綁定一樣。不採「作品上次用的 Route」當預設來源：追新番時作品多半沒送過單。從作品頁訂閱建的搜尋 Feed 只看那部作品那一種。
- **v1 與 v2 並存不取代**：同組同集兩份都入庫，使用者在 Jellyfin 選版本（brief §7.7、§18）。
